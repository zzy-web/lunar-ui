# 系统设计场景题

共 **15 题**，题号 **672–686**。 [返回分类总览](./)

> 答案用于面试复习与工程讨论，具体实现请结合项目锁定的版本验证。

## 672. 设计一个企业级 Agent 平台：租户、权限、工具、执行和观测体系如何组织？ {#q-672}

**参考答案：**

先定义租户与任务 SLO，控制面管身份/策略/工具目录，执行面用队列+Harness+隔离 Worker，数据面管 OLTP/对象/知识/记忆。贯穿授权、幂等、检查点、事件与计费，先单 Agent MVP，再用压测与故障演练扩展。

## 673. 设计智能客服 Agent：高并发、知识检索与人工转接如何实现？ {#q-673}

**参考答案：**

入口鉴权/限流，意图路由到受 ACL 保护的知识检索或窄业务工具，回复带证据。高并发用缓存和队列，置信/权限不足转人工并附摘要与来源；转接后避免机器人继续重复操作，评测解决率与错误答复。

## 674. 设计代码 Review Bot：Repo 权限、代码上下文和审查流程如何管理？ {#q-674}

**参考答案：**

使用最小权限仓库安装获取 PR diff 与相关上下文，在隔离环境分析，输出定位到变更行且有复现依据的评论。未授权 PR 不带高权凭据执行，评论去重并由维护者审查；测漏报、误报和有效修复率。

## 675. 设计 RAG + Agent 混合系统：何时检索、何时调用工具，如何编排？ {#q-675}

**参考答案：**

Router 判断资料问题走 RAG、实时/动作走工具，复杂任务由 Agent 在两者间迭代。统一来源、权限和状态，检索不足明确未知，写动作单独授权/幂等；评测证据质量与端到端成功，限制检索循环。

## 676. 设计多租户 SaaS Agent 产品：租户隔离、配额和计费如何实现？ {#q-676}

**参考答案：**

以可信租户身份贯穿 API、状态、向量、缓存、凭据和事件，按租户配额调度与计量结算。不同隔离等级分资源池，计费使用可对账用量账本，重复回调/重试不重复扣费，越权与公平性作为上线门禁。

## 677. 设计内部知识问答 Agent：Confluence 等知识源如何接入并保持权限与内容同步？ {#q-677}

**参考答案：**

连接器按源权限拉取 Confluence 等内容，保存文档版本/ACL/来源并增量同步更新和删除。查询时先过滤、生成前复核，答案带引用；同步延迟监控和空结果处理关键，用户撤权不能只等下一次全量索引。

## 678. 设计销售辅助 Agent：CRM 实时数据如何接入，如何控制更新与跟进操作？ {#q-678}

**参考答案：**

CRM 通过窄工具实时查询客户/商机，生成建议与草稿；更新字段、发送跟进等按授权预览确认并用幂等键。绑定记录版本防覆盖销售人工修改，日志脱敏，评估建议有效率与误更新/重复外发。

## 679. 设计运维 On-call Agent：告警聚合、故障诊断和处置审批如何组织？ {#q-679}

**参考答案：**

告警去重聚合后用只读工具查指标/日志/发布，生成带证据诊断和处置方案。自动化仅限授权低风险动作，高风险需审批，超时转人工；记录执行与回滚，评测诊断时间和错误处置率。

## 680. 设计多模态客服 Agent：图片、音频与文本输入如何统一处理？ {#q-680}

**参考答案：**

统一附件 ID/身份，图片 OCR/视觉、音频 ASR 与文本意图合并，证据保留页码/坐标/时间。查询知识或业务工具后输出文本/可选语音，低置信转人工，控制敏感数据、模态成本与实时打断。

## 681. 设计 Agent Marketplace：第三方 Agent 或工具如何接入、审核和分发？ {#q-681}

**参考答案：**

第三方提交清单、schema、版本、签名与权限声明，审核后沙箱测试/上架，用户按作用域授权。运行经统一工具代理与计量，依赖/描述更新需再审，支持举报、撤销、隔离和回滚，禁止隐式跨租户数据共享。

## 682. 设计跨境电商 Agent：多语言、多区域和业务操作如何支持？ {#q-682}

**参考答案：**

多语言意图与商品实体统一，区域路由满足库存/币种/税费数据与数据驻留要求。订单/退款等用实时权威 API、幂等与审批，报价明确时效/币种；评测语言质量、金额正确性和跨区故障，不让模型计算最终应付款。

## 683. 设计研发平台内置 Agent：与 IDE、代码仓库和 CI/CD 如何集成？ {#q-683}

**参考答案：**

IDE 提交目标与选区/仓库版本，后端 Harness 在隔离分支/worktree 检索、改代码、运行 CI 并生成 PR。工具按仓库授权，事件驱动进度/diff，人工审查后合并；测试反馈闭环、凭据隔离和可回滚为核心。

## 684. 设计教育场景 Agent：防作弊、学习引导和使用边界如何设置？ {#q-684}

**参考答案：**

按年龄/课程/场景区分练习、反馈与考试，优先给提示和步骤检查，限制代答或越权查看。保存必要学习进度并最小化个人数据，教师可设置边界与审核；评测学习提升、公平性、误判和泄露，而非只看答题正确率。

## 685. 设计金融 advisory Agent：免责声明、权限边界和人工审核如何落地？ {#q-685}

**参考答案：**

先划定教育信息、研究辅助与受监管建议的产品边界，由适用地区专业人员审核。数据有来源/时效，身份适当授权，关键建议与交易人工审核、审计；免责声明不能替代法定义务，也不能让模型自行扩大可执行权限。

## 686. 设计从 0 到 1 的 Agent 产品：MVP 范围、架构和上线评测如何规划？ {#q-686}

**参考答案：**

选单一高价值且可验证场景，定义用户、验收、工具和禁区，用简单单 Agent/Workflow 做 MVP。最初就有授权、幂等、状态、预算和观测，离线评测后小流量上线，按成功任务成本/反馈决定扩功能。
