# MCP 协议

共 **15 题**，原始题号 **492–506**。 [返回分类总览](./)

> 答案用于面试复习与工程讨论；【推导】保留原文标记，表示题意依据不完整截图补全。实现细节请结合项目锁定的版本验证。

## 492. 【推导】MCP 是什么？Host / Client / Server 分别承担什么职责？ {#q-492}

**参考答案：**

MCP 是连接 AI 应用与外部能力的开放协议；Host 管理用户交互、策略与模型，Client 在 Host 中维护与 Server 的协议连接，Server 暴露工具、资源和提示。一个 Host 可管理多个 Client/Server 连接。

## 493. 【推导】MCP 和直接 Function Calling 加 API 封装有什么区别？分别适合哪些场景？ {#q-493}

**参考答案：**

直接 Function Calling + API 封装更轻、业务可控；MCP 提供标准能力发现和连接协议，方便多宿主复用。MCP 并不替代业务 API 或模型调用，也不自动带来安全与高质量工具设计。

## 494. 【推导】MCP 的 tools、resources、prompts 分别是什么？如何区分和使用？ {#q-494}

**参考答案：**

tools 是可调用动作，resources 是按 URI 提供的可读上下文，prompts 是可复用提示模板。通常分别由模型选择、应用管理和用户触发，但宿主体验不同；能力是否可用需初始化协商。

## 495. 【推导】设计一个 MCP Server 要暴露哪些能力？如何划分工具、资源和提示模板？ {#q-495}

**参考答案：**

围绕业务能力暴露少量窄工具，把可读文档设计为资源，把用户可选工作模板设计为 prompts。定义 schema、错误、分页与副作用，加入身份、授权、限流和审计；避免把整个内部 API 原样镜像。

## 496. 【推导】MCP 传输层 stdio / SSE / Streamable HTTP 有什么区别？如何选择？ {#q-496}

**参考答案：**

stdio 常由客户端启动本地子进程，通过标准输入输出传 JSON-RPC；Streamable HTTP 适合远程服务，可按需使用 SSE。旧 HTTP+SSE 传输与新传输不是同一接口，需明确协议版本。[传输规范](https://modelcontextprotocol.io/specification/2025-06-18/basic/transports)

## 497. 【推导】MCP 在 Agent 系统架构里通常处于哪一层，与模型和业务服务如何协作？ {#q-497}

**参考答案：**

MCP 常处于工具/上下文接入层，运行时将 Server 能力映射为模型可见定义并执行请求，结果再回到 Agent Loop。业务授权仍在服务端和 Host 强制，MCP 不负责替模型规划所有步骤。

## 498. 【推导】MCP 鉴权、租户隔离和安全边界应该如何设计？ {#q-498}

**参考答案：**

远程连接按协议认证，服务器验证 token 的签发者、受众与作用域，并在每次操作强制租户/资源 ACL。stdio 使用本地进程权限边界；禁止 token 透传和无约束下游调用，会话 ID 不能当作认证凭据。

## 499. 【推导】多个 MCP Server 并存时，Client 如何管理连接、工具发现和命名冲突？ {#q-499}

**参考答案：**

每个 Server 独立连接和能力缓存，工具名加入 server/domain 命名空间，保留原始映射。初始化协商版本和能力，监听列表变更并刷新；设置独立超时、断路与最小权限，避免一个 Server 故障阻塞全部。

## 500. 【推导】MCP tool 调用结果怎么和 Agent 上下文衔接？如何控制结果大小与信息质量？ {#q-500}

**参考答案：**

将结果按调用 ID 关联并转成受限的工具消息，保留结构化字段、来源和资源链接。大对象分页或存外部引用，进行脱敏和大小控制；返回文本不能升级为系统指令。

## 501. 【推导】MCP 连接断开、Server 崩溃或调用超时时，如何恢复与处理失败？ {#q-501}

**参考答案：**

分类连接故障和业务失败，清理失效会话后按协议重新初始化/恢复并刷新工具目录。读操作可有界重试，写操作先查询幂等结果；取消和超时不代表远端工作已经停止，必须核实最终状态。

## 502. 【推导】MCP resources（可读资源）和 tools 有什么区别？什么时候应该使用资源？ {#q-502}

**参考答案：**

resources 适合 URI 标识的文档、配置、日志等可读上下文，可支持模板或订阅；tools 适合带参数的动作与计算查询。两者都需访问控制；不要仅因资源“只读”就暴露整个文件系统。

## 503. 【推导】MCP prompts（服务端提示模板）有什么作用？如何与 Agent 自身的 Prompt 配合？ {#q-503}

**参考答案：**

prompts 是 Server 提供的参数化提示模板，便于用户选择特定工作流。Host 读取后结合自身可信规则和本次输入使用，模板不能覆盖更高优先级策略或自行授权危险操作。

## 504. 【推导】MCP Server 怎么做版本兼容和能力协商，避免升级影响客户端？ {#q-504}

**参考答案：**

初始化交换协议版本和能力，对新增字段保持兼容，对破坏性 schema 变更采用新工具名/版本并提供迁移期。客户端仅使用协商后的能力，测试旧新版本组合，不应假设升级后工具参数永远不变。

## 505. 【推导】本地 MCP（stdio）和远程 MCP 在部署、鉴权、安全和运维方面有什么区别？ {#q-505}

**参考答案：**

stdio 依赖本地进程分发、环境和操作系统权限，部署简单但可访问本机资源；远程 MCP 需网络认证、TLS、多租户隔离、连接与运维治理。两者都需要可信来源、版本固定和敏感参数保护。

## 506. 【推导】怎么测试和观测一个 MCP Server？应该覆盖哪些功能、异常和性能指标？ {#q-506}

**参考答案：**

测试初始化、能力协商、工具/资源/模板、schema 校验、取消、超时、断连、权限和恶意输入。监控调用成功率、P95 延迟、连接数、结果大小与错误分布；用协议一致性测试加真实宿主集成验证。
