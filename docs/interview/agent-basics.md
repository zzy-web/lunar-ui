# Agent 基础

共 **30 题**，题号 **309–338**。 [返回分类总览](./)

> 答案用于面试复习与工程讨论，具体实现请结合项目锁定的版本验证。

## 309. AI Agent 到底是什么？它和 Chatbot 有什么区别？ {#q-309}

**参考答案：**

Agent 围绕目标循环观察环境、选择动作、执行工具并根据反馈调整，Chatbot 主要提供对话回复。两者有重叠，区别看执行闭环和自主范围，而不是 UI 是否是聊天框。

## 310. 一个 Agent 最小可运行闭环应该包含哪些组件与步骤？ {#q-310}

**参考答案：**

最小闭环包含目标/状态、模型、工具、执行器和停止条件：组装上下文→模型决策→校验并执行动作→写回结果→验证完成或继续。必须有步数/时间上限与错误处理，避免无限循环。

## 311. 为什么说 Agent 不等于“LLM + 工具”？还需要哪些机制？ {#q-311}

**参考答案：**

仅有模型和工具没有可靠运行边界，还需要状态持久化、授权、调度、重试、幂等、取消、观测和评测。生产 Agent 的可信性来自整个系统对执行过程的约束，而不只是模型聪明程度。

## 312. 判断一个需求是否适合用 Agent，应该考虑哪些因素？ {#q-312}

**参考答案：**

任务需存在不确定步骤、可用反馈和可验证目标，且收益超过延迟/成本/风险时才适合 Agent。规则清晰、操作固定时优先普通工作流，证据不足或副作用不可控时应限制自主性。

## 313. Agent 最容易被误用在哪些场景？ {#q-313}

**参考答案：**

常见误用包括用 Agent 替代简单 CRUD/确定性批处理，让其自主做不可逆高风险决策，以及没有工具和验证却要求可靠完成任务。先定义业务验收与人工边界，再决定是否需要模型规划。

## 314. Agent 的自主性应该如何分级设置？不同级别应该有哪些权限和人工介入要求？ {#q-314}

**参考答案：**

可分为只建议、授权后执行、受限自主和更高自主等级；每级规定工具、资源、金额、时间和人工检查点。风险不是单一开关，应按动作动态判断，授权过期或条件变化时重新验证。

## 315. Agent 的任务边界应该如何定义？ {#q-315}

**参考答案：**

用目标、非目标、输入范围、可操作资源、允许工具、预算和验收条件定义边界。把用户模糊表达转为可检查任务契约；出现范围扩张或关键选择缺失时先澄清，而非自行无限扩展。

## 316. Agent 的状态、上下文和记忆有什么区别？分别应该保存什么信息？ {#q-316}

**参考答案：**

状态是程序事实，如 run 阶段/结果/审批；上下文是本次模型可见材料；记忆是跨轮次/任务复用的信息。状态应权威持久化，上下文可裁剪，记忆需要来源、期限和用户隔离。

## 317. 为什么聊天历史不能替代结构化状态？结构化状态应该如何设计？ {#q-317}

**参考答案：**

聊天文本含歧义、重复与裁剪，不能可靠表示事务、并发和最终结果。结构化状态至少包括 runId、status、step、version、toolCalls、审批与结果引用，并用状态机和原子更新保证合法流转。

## 318. Agent 的规划应该一次生成完整计划，还是边执行边调整？如何选择？ {#q-318}

**参考答案：**

固定流程可预先计划，不确定环境更适合粗粒度计划加逐步重规划。计划不是承诺所有后续动作都已授权；保留已完成证据，遇新约束、失败或预算变化时修订剩余步骤。

## 319. 哪些决策适合交给模型，哪些必须由确定性程序控制？ {#q-319}

**参考答案：**

模型适合语义理解、候选方案和不确定任务分解；鉴权、金额计算、事务、状态转换、预算与停止上限必须由确定性程序控制。把模型输出视作建议，校验后才转为实际动作。

## 320. Agent Runner 在系统里解决什么问题？应该负责哪些执行与控制逻辑？ {#q-320}

**参考答案：**

Runner 驱动模型与工具循环，维护 run 状态、事件、预算、超时、取消和终止。它协调持久化与恢复，不应把全部领域逻辑塞进循环；工具执行和权限检查可以由独立 runtime 承担。

## 321. Agent 工具应该如何设计，才适合模型理解、选择和可靠调用？ {#q-321}

**参考答案：**

用业务意图命名窄工具，输入 schema 明确类型/枚举/边界，说明读写副作用、权限、幂等和错误。返回信息可验证且可继续决策；隐藏凭据、内部实现和任意执行能力。

## 322. 工具返回结果应该如何组织，才能支持 Agent 后续决策与执行？ {#q-322}

**参考答案：**

结果应包含结构化业务数据、success/error、可重试标志、来源、时间和分页/资源引用。内容太大先摘要再提供读取入口，错误要可定位；不可信返回不能成为新的高优先级指令。

## 323. Agent 的读工具和写工具应该如何区分，并设置对应的权限和执行流程？ {#q-323}

**参考答案：**

读工具也需租户与资源授权，写工具额外需要意图/参数验证、幂等、并发控制与审计。按副作用风险和已有授权决定是否人工确认，不能把所有读取视作无风险或所有写入都无限自动化。

## 324. 为什么幂等性是 Agent 写操作工具的重要要求？如何避免重复执行造成副作用？ {#q-324}

**参考答案：**

超时和重放会使同一写动作执行多次。以稳定操作 ID/幂等键绑定参数，在事务或唯一约束下记录执行结果，恢复时查询结果后决定续跑；不能仅依赖模型记得“已经做过”。

## 325. Agent 什么时候需要让用户介入？ {#q-325}

**参考答案：**

关键输入缺失、授权不足、不可逆高风险动作、证据冲突或预算耗尽且无法自动恢复时需要用户介入。提供具体选择、影响与当前证据，等待答复期间可继续独立安全工作，但不能把沉默当授权。

## 326. 前端如何展示 Agent 的执行过程、当前状态和等待用户处理的事项？ {#q-326}

**参考答案：**

展示用户能理解的阶段、工具摘要、运行/等待/失败状态和最终产物，等待审批时突出动作与影响。前端按服务端事件和快照驱动，避免假进度；内部推理、敏感参数和原始日志不直接展示。

## 327. Agent 常见失败类型有哪些？ {#q-327}

**参考答案：**

常见有理解/规划错误、工具选错或参数错、检索无证据、权限拒绝、依赖故障、循环、状态竞争和质量不达标。用失败分类关联 trace，再决定改模型、Prompt、工具、数据或运行控制。

## 328. Agent 的基础指标应该怎么设计？ {#q-328}

**参考答案：**

核心指标是任务成功率和每次成功任务成本，辅以质量、首响应/总延迟、工具错误、人工接管、重试、取消和安全违规。按任务类型/租户/版本分组，不能只用 token 数评价业务价值。

## 329. 如何为 Agent 设计离线测试集？ {#q-329}

**参考答案：**

从真实任务抽样并脱敏，涵盖典型、边界、失败恢复和攻击案例，标注验收与允许动作。隔离训练/调优与测试集，固定环境、工具状态和版本，必要时多次运行报告波动。

## 330. Prompt 在 Agent 里负责什么，哪些能力应该由程序和工具实现？ {#q-330}

**参考答案：**

Prompt 表达角色、任务、证据使用和输出契约；鉴权、持久化、事务、预算、校验和副作用控制由程序实现。不要把“不要越权”当作访问控制，也不要依赖自然语言记录唯一业务状态。

## 331. Agent 的控制平面和执行平面怎么划分，分别承担哪些职责？ {#q-331}

**参考答案：**

控制平面管理租户、配置、模型、策略、发布和任务元数据；执行平面运行模型/工具任务并产生事件。两者通过版本化契约连接，执行单元故障不应破坏控制数据，策略在执行时仍需验证。

## 332. Agent 如何防 Prompt Injection？如何区分可信指令与不可信内容？ {#q-332}

**参考答案：**

将外部网页、检索和工具输出视为数据，标注来源并限制上下文影响；执行侧最小权限、参数校验和敏感动作授权。检测与过滤辅助告警，不能证明绝对安全，需红队验证与隔离降低后果。

## 333. 成本和延迟为什么是 Agent 基础设计的一部分？如何设置预算与控制机制？ {#q-333}

**参考答案：**

多轮模型和工具调用会叠加成本与延迟，可能放大失败和滥用。设置 run 级 token/调用/时间预算与租户配额，按步骤选择模型和并行度，超限时给出部分结果或降级而不是无限继续。

## 334. Agent 日志和审计最少应该记录哪些信息？ {#q-334}

**参考答案：**

记录主体/租户、runId、配置版本、阶段、工具操作与授权结果、时间、用量、错误和产物引用。业务审计偏重谁对什么做了什么，调试日志可采样；敏感数据脱敏并控制访问和保留周期。

## 335. 多用户并发场景下，Agent 基础设施如何实现状态隔离、资源管理和任务调度？ {#q-335}

**参考答案：**

以 tenantId/userId/sessionId/runId 分层隔离，数据库和缓存强制作用域，队列按租户公平调度。采用并发配额、资源池、租约与状态版本，避免同一 run 重复领取或噪声租户耗尽全部资源。

## 336. Agent、RAG、Memory、Tool 分别是什么关系？如何组合成完整系统？ {#q-336}

**参考答案：**

Agent 负责行动决策与闭环，RAG 提供外部知识证据，Memory 保存可复用经验/偏好，Tool 执行查询和操作。运行时在权限与预算下组合它们，并用状态和验证确保最终完成。

## 337. 从 Demo Agent 走向生产级 Agent，需要补齐哪些能力？ {#q-337}

**参考答案：**

优先补齐可验证目标、工具契约、授权隔离、状态持久化、幂等恢复、预算取消和观测。随后建立真实评测集、灰度与回滚，再优化模型、检索和吞吐，不应只扩充 Prompt。

## 338. 如果只能用一句话定义生产级 Agent，你会如何描述？ {#q-338}

**参考答案：**

生产级 Agent 是在明确授权、预算和可观测执行边界内，能够调用工具、持久化状态、验证结果并从失败中恢复的目标执行系统。
