# Prompt 上下文工程

共 **16 题**，题号 **240–255**。 [返回分类总览](./)

> 答案用于面试复习与工程讨论；【推导】保留原文标记，表示题意依据不完整截图补全。实现细节请结合项目锁定的版本验证。

## 240. 【推导】Agent 的 System Prompt 怎么设计？应该包含哪些职责、边界和约束？ {#q-240}

**参考答案：**

System Prompt 明确角色、目标、可用能力、可信来源、决策原则、输出契约和失败处理。权限与预算由运行时强制执行，Prompt 只表达意图；规则应短而具体，并避免相互矛盾。

## 241. 【推导】Agent 场景下 Few-shot 样例怎么选择、组织和维护？ {#q-241}

**参考答案：**

选择覆盖常见、边界和失败情况的少量高质量样例，保持输入、工具行为和输出格式一致。按任务相关性动态选择，版本化并防止评测泄漏；不要堆积大量近似样例占满上下文。

## 242. 【推导】正向指令和负向禁令哪个在生产环境中更有效？如何组合使用？ {#q-242}

**参考答案：**

正向说明“应该怎样做”通常更可执行，负向禁令用于明确高风险边界。组合成替代行为，例如缺证据时说明未知并检索，而非只说不要编造；效果需通过攻击与业务测试验证，不存在普适优胜模板。

## 243. 【推导】Prompt 中的分隔符和结构化块（XML 等）有什么作用？如何组织不同来源的信息？ {#q-243}

**参考答案：**

分隔符、XML/JSON 块帮助标识指令、上下文、用户输入和检索证据，降低格式歧义并便于程序解析。但标签本身不是安全边界，外部内容仍须按不可信数据处理，权限必须在工具层约束。

## 244. 【推导】动态 Prompt 拼装怎么做？模板、变量和条件内容如何管理？ {#q-244}

**参考答案：**

使用版本化模板与类型化变量，按任务、权限、模态等条件加载片段，插入前做转义与长度检查。记录模板版本和变量摘要便于回放；固定内容置前，避免把未清洗用户输入拼成可信规则。

## 245. 【推导】RAG 检索块注入 Prompt 时，格式、来源和引用信息应该如何组织？ {#q-245}

**参考答案：**

每块携带稳定 chunkId、文档标题、来源地址、版本/时间与原文片段，明确标记为证据数据。要求答案引用块标识并由程序验证引用存在；检索前后都检查 ACL，不能通过引用暴露无权文档。

## 246. 【推导】上下文预算怎么在 system、tool、历史消息和检索内容之间分配？ {#q-246}

**参考答案：**

先预留输出和推理空间，再给必须规则/当前请求，随后按价值分配工具、历史和证据。用实际 tokenizer 计算，给工具结果设截断与摘要策略；关键约束应持久存储，不能任由历史裁剪丢失。

## 247. 【推导】每轮 Prompt 用全量聊天历史还合适吗？如何裁剪、压缩和选择历史内容？ {#q-247}

**参考答案：**

短会话可全量发送，长会话宜保留近期轮次、任务摘要、明确约束与按需检索事实。摘要附来源和未完成事项，重要工具结果存外部；裁剪不能打乱工具调用及对应结果的协议配对。

## 248. 【推导】Prompt 里怎么引导模型正确表达不确定性，避免编造答案？ {#q-248}

**参考答案：**

明确区分已知事实、推断和未知，要求不足时检索或澄清并引用证据。加入缺证据的拒答样例与校验器，关键数字通过工具验证；让模型报一个置信分数不能代替外部验证。

## 249. 【推导】输出格式约束应该放在 System 还是 User 消息里？如何保证约束一致？ {#q-249}

**参考答案：**

稳定格式契约放可信系统/developer 配置，用户消息表达本次内容与被允许的格式选择；可使用 schema 强约束。组装时解决冲突，响应后验证结构并处理拒答/截断，不能只靠“请输出 JSON”。

## 250. 【推导】Prompt 层除关键词过滤外，纵深防御应该怎么做？ {#q-250}

**参考答案：**

结合输入来源分级、检索隔离、工具白名单、参数校验、最小权限、输出审查和风险审批。检测可疑文本可作信号，但不能保证阻止注入；安全动作由运行时策略执行而非只依赖关键词或 Prompt。

## 251. 【推导】用户输入和外部文档在 Prompt 中应该如何区分和隔离，避免被当作高优先级指令？ {#q-251}

**参考答案：**

用户需求与外部证据分块标注角色、来源和可信级别，检索文本只能作为待分析数据，不能覆盖系统规则。运行时校验每次工具参数及授权，机密不进入模型上下文；单纯加引号不是完整防注入机制。

## 252. 【推导】Prompt 怎么引导模型在 tool call 和直接回答之间做出合理选择？ {#q-252}

**参考答案：**

说明需要实时、私有或可验证事实时用工具，已有充分证据的稳定知识可直接答，缺少关键参数时先澄清。工具描述要突出适用/禁用场景，并设置调用预算和结果验证，避免无意义重复调用。

## 253. 【推导】长任务 Agent 的上下文摘要机制怎么设计？如何保留关键事实、决策和待办事项？ {#q-253}

**参考答案：**

按阶段或 token 阈值生成摘要，保留目标、约束、关键事实及来源、已完成步骤、失败尝试和待办。结构化状态作为事实源，摘要仅辅助模型；存版本与原始事件关联，防止压缩累计漂移。

## 254. 【推导】生产环境 Prompt 版本管理和灰度发布怎么做？ {#q-254}

**参考答案：**

Prompt 与工具 schema、模型配置一同版本化，经过评测和小流量灰度发布，记录每个 run 的版本。保留快速回滚与兼容策略；不要在进行中的任务中随意切换规则。

## 255. 【推导】Prompt 变更怎么评测？A/B 实验和回归测试如何设计？ {#q-255}

**参考答案：**

建立常见、困难、安全及历史事故用例，比较任务成功、工具行为、格式、成本和延迟。线上按用户/租户稳定分流做 A/B，控制模型和数据变量，明确显著性与回滚阈值，避免只看几个好例子。
