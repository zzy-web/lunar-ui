# Agent UI 前端交互

共 **15 题**，题号 **550–564**。 [返回分类总览](./)

> 答案用于面试复习与工程讨论；【推导】保留原文标记，表示题意依据不完整截图补全。实现细节请结合项目锁定的版本验证。

## 550. 【推导】前端 Agent UI、Harness 事件和后端执行状态如何关联与同步？ {#q-550}

**参考答案：**

前端保存 runId/sessionId 与最后事件序号，按 envelope 更新本地视图，后端持有权威状态。重连先续传或拉快照再接流，终态、审批与错误均用明确事件，避免把文本流结束误认作任务完成。

## 551. 【推导】Copilot 式与 Autonomous 式 Agent 的前端交互设计有什么区别？ {#q-551}

**参考答案：**

Copilot UI 强调建议预览、选择和确认，Autonomous UI 强调长期进度、可见范围、暂停/取消和异常接管。两者都应呈现产物与证据，按动作风险提供审批，不让自主模式隐藏关键副作用。

## 552. 【推导】流式输出在 UI 层怎么渲染？Markdown 增量更新和不完整内容如何处理？ {#q-552}

**参考答案：**

按块/帧批量追加文本，避免每 token 全文重渲染；对未闭合代码块/Markdown 使用增量解析或暂存。清洗 HTML 和链接，完成后统一校验渲染，长消息与消息列表虚拟化，不能直接执行模型生成 HTML。

## 553. 【推导】Tool 调用过程怎么展示？折叠卡片里应该呈现哪些状态、输入和结果？ {#q-553}

**参考答案：**

工具卡展示名称/目的、排队/运行/成功/失败/取消、耗时、脱敏输入与结果摘要，详情按需展开。稳定 callId 保证事件归属，失败提供可执行恢复入口，内部凭据与原始大对象不展示。

## 554. 【推导】要不要展示 thinking / 推理过程？如何区分用户可见的执行摘要与模型内部推理？ {#q-554}

**参考答案：**

展示可供用户核验的计划、动作摘要、证据和结果，而非模型隐藏内部思维链。若平台提供可公开摘要，应标明其语义；工具日志也需脱敏，界面不能把生成的“思考中”文本当真实执行进度。

## 555. 【推导】HITL 审批、改 plan、补表单在前端怎么交互，如何与执行流程衔接？ {#q-555}

**参考答案：**

显示具体动作、资源、影响、可编辑字段和批准/拒绝，提交包含 approvalId、runId 与版本。后端校验审批人、参数和期限后原子恢复；UI 处理重复点击、过期和并发取消，不只在前端切换状态。

## 556. 【推导】用户点停止/取消，前端状态和 UI 应该如何变化，如何同步后端执行结果？ {#q-556}

**参考答案：**

点击后立即显示“正在停止”并发送取消请求，后端中止可取消工作、确认最终状态后再标 cancelled。保留部分结果与已发生副作用，处理取消时已完成的竞态；关闭流连接不等于取消 run。

## 557. 【推导】长任务、后台跑时前端怎么保持进度同步，并支持离开后返回查看？ {#q-557}

**参考答案：**

run 状态与事件持久化，前端保存 ID/游标，离开后任务由后台执行。返回先拉快照并续传，展示完成产物或待处理项；实时连接只是订阅，不应决定任务是否继续运行。

## 558. 【推导】Agent 报错、tool 失败、空检索等异常应该怎么展示，如何提供恢复入口？ {#q-558}

**参考答案：**

区分工具/网络/权限/模型/空检索错误，用用户可理解的原因和恢复选择展示。可重试读操作提供重试，写操作先核验状态；保留已完成产物和追踪 ID，避免只显示“发生错误”。

## 559. 【推导】多轮会话、多 tab、多 run 并行时，前端如何组织状态与消息归属？ {#q-559}

**参考答案：**

状态按 tenant/session/run/message/toolCall 分层存储，每条事件明确归属与序号，路由切换不改变后台任务所有者。独立订阅/取消，避免全局一个 loading 标志，消息去重并处理过期请求返回。

## 560. 【推导】用户上传文件、选中上下文、@引用时，前端如何组织输入与展示来源？ {#q-560}

**参考答案：**

上传先生成受控 attachmentId，输入中用引用块保留文件、选区、路径及版本，UI 可查看来源。后端重新鉴权读取，用户可移除/更改上下文；不要把本机路径显示出来就假设服务端能访问。

## 561. 长会话消息列表怎么保性能？ {#q-561}

**参考答案：**

消息列表虚拟化，Markdown 分块缓存、流式更新节流，附件懒加载，历史按游标分页。维护滚动锚点和“回到底部”提示，用户向上阅读时不强制跳底；控制单条巨大消息的渲染成本。

## 562. 【推导】可编辑产物（代码 diff、文档草稿等）如何在 Agent UI 中展示、修改和确认？ {#q-562}

**参考答案：**

产物作为独立版本化对象展示，代码用 diff、文档用编辑器，用户编辑记录修订。确认绑定具体版本/hash，后端检查冲突后应用；模型后续改动不能覆盖未提交编辑，支持预览与回退。

## 563. 【推导】前端怎么测 Agent UI？不只测组件，还应该覆盖哪些交互、事件和异常场景？ {#q-563}

**参考答案：**

测试事件重复/乱序/断线、取消完成竞态、审批过期、工具失败、刷新恢复和多 run 隔离。用假事件流做组件/状态测试，再 E2E 验证键盘可访问性、滚动和弱网行为，而非只截聊天框快照。

## 564. 【推导】Demo 只有一个 ChatGPT 对话框，走向生产级 Agent UI 还需要补哪些能力？ {#q-564}

**参考答案：**

补任务状态、工具卡、产物预览/编辑、授权审批、取消恢复、来源引用、附件管理与历史。还需错误恢复、可访问性、多 run 隔离、观测和前后端一致性，核心是可靠执行交互而非更多气泡样式。
