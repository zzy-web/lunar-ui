# Agent Skill

共 **20 题**，题号 **289–308**。 [返回分类总览](./)

> 答案用于面试复习与工程讨论；【推导】保留原文标记，表示题意依据不完整截图补全。实现细节请结合项目锁定的版本验证。

## 289. 【推导】Agent Skill 是什么？和 Tool、MCP 有什么区别？ {#q-289}

**参考答案：**

Skill 是面向任务的可加载说明及可选脚本/资源；Tool 提供实际动作，MCP 提供外部能力接入协议。Skill 可指导如何选择工具，但本身不赋予权限，也不等于一个常驻独立 Agent。

## 290. 【推导】SKILL.md 标准结构应该有哪些内容？如何组织元信息、执行说明和支持资源？ {#q-290}

**参考答案：**

常见 SKILL.md 包含 YAML 元信息（name、description）与 Markdown 执行指南，说明触发范围、输入、步骤、产物和验证。支持脚本、references、assets 按需读取；具体可选字段及目录约定以宿主规范为准。

## 291. 【推导】Skill 的 description 和触发机制有什么关系？如何提高触发准确率？ {#q-291}

**参考答案：**

description 用来帮助宿主/模型判断何时加载 Skill，应写明具体任务、输入及不适用情况。通过正例和近似负例测试误触发/漏触发，避免宽泛关键词；触发规则不是所有产品通用的固定算法。

## 292. 【推导】Skill、Cursor Rule、Subagent 分别适合解决什么问题？如何选择？ {#q-292}

**参考答案：**

Rule 适合持续生效的项目规范，Skill 适合按需执行的工作方法，Subagent 适合隔离上下文与任务执行。先用最简单机制，只有独立目标/并行收益明确时再用子代理；格式与优先级受宿主约束。

## 293. 【推导】Skill 和 MCP 在架构里怎么配合？如何分工和组织调用流程？ {#q-293}

**参考答案：**

Skill 描述做事流程，MCP 提供读取或写入外部系统的工具。流程是识别任务→加载 Skill→发现授权工具→执行与校验→产出结果，工具不可用时报告缺失而非编造执行成功。

## 294. 【推导】多个 Skill 并存时，优先级、冲突和重复能力应该如何处理？ {#q-294}

**参考答案：**

先遵循宿主的系统/用户优先级，再按明确的适用范围选择 Skill；冲突时缩小职责并消除重复，不靠任意文件排序猜测。高风险冲突应明确指出，Skill 不能覆盖用户约束或运行时策略。

## 295. 【推导】团队里怎么版本化、共享和审查 Skill？ {#q-295}

**参考答案：**

在版本库中审查说明、脚本与依赖，标记维护者、适用版本和变更记录，通过组织目录或受控包分发。CI 检查结构并执行代表性任务，固定依赖，提供弃用和回滚机制。

## 296. 【推导】怎么写一个高质量 Skill，避免空泛描述和无法执行的步骤？ {#q-296}

**参考答案：**

描述清晰边界，用真实命令/工具契约、输入输出例子和可验证完成条件编排步骤。把长参考按需拆出，说明失败处理与清理；避免重复系统规则、不可执行口号和未经测试的假路径。

## 297. 【推导】Progressive disclosure（按需读取）在 Skill 中如何实现？如何减少上下文占用？ {#q-297}

**参考答案：**

目录只暴露 name/description 等轻元信息，命中后读取主说明，再按当前步骤读取特定参考或脚本。避免递归把所有附件灌入上下文，给资源添加清晰索引和读取条件。

## 298. 【推导】Skill 的安全边界是什么？能指导 Agent 做哪些事，哪些权限不能仅靠 Skill 授予？ {#q-298}

**参考答案：**

Skill 可提供方法、约束与验证要求，但执行权来自用户授权、宿主策略和工具访问控制。脚本仍属于可执行供应链，不能因为在 Skill 目录中就绕过沙箱、泄露凭据或执行未授权写入。

## 299. 【推导】工作流类 Skill 怎么拆步骤和输出要求，确保执行过程清晰且结果可验证？ {#q-299}

**参考答案：**

按输入检查、规划、执行、验证、交付分阶段，步骤给出前置条件、输出与失败分支。不可逆动作前准备可审查结果并按风险审批，可恢复步骤保存检查点；避免把所有步骤写成无条件流水线。

## 300. 【推导】怎么测试 Skill 是否被正确触发、正确执行并产出预期结果？ {#q-300}

**参考答案：**

测试应包含应触发与不应触发的请求、缺文件/工具失败/权限不足等情形。验证是否正确加载资源、遵循步骤、产物可用且副作用符合授权，记录耗时和 token 开销作为回归基线。

## 301. 【推导】Skill 在 Cursor、Claude Code 等不同工具中如何复用？有哪些兼容性问题？ {#q-301}

**参考答案：**

可复用通用 Markdown 方法和脚本，但目录发现、frontmatter、工具名、路径及优先级可能不同。维护可移植核心与宿主适配层，在目标产品实际验证；不能假设复制文件后权限与触发行为完全相同。

## 302. 【推导】什么时候该把 Prompt 模板或 Workflow 封装成 Skill？ {#q-302}

**参考答案：**

当同一类任务反复出现、有稳定输入输出、流程依赖和质量标准时适合封装 Skill。一次性短问答或持续规范未必适合，前者直接提示即可，后者通常用 Rule；封装前验证能节省维护成本。

## 303. 【推导】生产 Agent 产品要不要开放用户自定义 Skill？如何管理权限和风险？ {#q-303}

**参考答案：**

可开放，但应隔离安装来源、依赖、文件和网络权限，审查脚本并对写入/高风险行为采用运行时授权。租户 Skill 不得污染其他租户，支持签名/版本、禁用、审计和配额，防止把模板功能变成任意执行入口。

## 304. 【推导】Skill catalog 怎么组织？发现与检索机制应该如何设计？ {#q-304}

**参考答案：**

按领域、任务、输入类型与权限标签组织目录，使用 name/description 搜索并过滤不可用能力。排序结合相关性、可信度和版本，保留稳定 ID；工具多时先加载元信息，避免全量载入。

## 305. 【推导】Skill 的 token 预算怎么估？怎么控制加载与执行时的上下文成本？ {#q-305}

**参考答案：**

预算包括元信息、主说明、按需参考、工具结果及产物回传，用目标 tokenizer 和真实任务统计。给长文与输出设上限、按阶段加载，记录命中与收益；压缩不能丢掉关键前置条件和验证要求。

## 306. 【推导】Skill 和用户画像 / 记忆系统怎么配合，避免职责混淆和信息过期？ {#q-306}

**参考答案：**

Skill 保存稳定方法，画像保存用户偏好，记忆保存可追溯事实与经历。执行时按权限/时间读取偏好参数，不把临时事实硬编码进通用 Skill；冲突时核对当前用户意图并更新过期记忆。

## 307. 【推导】子代理 + Skill 模式怎么设计？如何控制质量、任务分工与执行成本？ {#q-307}

**参考答案：**

主代理给子代理明确子目标、输入、权限、预算和验收条件，子代理加载匹配 Skill 完成任务并回传证据。限制并发与工具权限、避免重复写同一资源，由主代理整合并验证，而非靠多代理互相肯定质量。

## 308. 【推导】Skill 失效、过时和误触发怎么治理？ {#q-308}

**参考答案：**

设维护人、支持版本、自动回归与线上反馈，监控触发准确率和完成率。过时 Skill 标记弃用、限制加载并迁移用户，误触发时收窄 description 与边界；保留回滚和禁用开关。
