# LangGraph 与框架选型

共 **24 题**，题号 **365–388**。 [返回分类总览](./)

> 答案用于面试复习与工程讨论；【推导】保留原文标记，表示题意依据不完整截图补全。实现细节请结合项目锁定的版本验证。

## 365. 【推导】LangGraph 在 Agent 技术栈里解决什么问题？ {#q-365}

**参考答案：**

LangGraph 用图表示有状态执行，支持条件路由、循环、检查点、中断与恢复，适合长任务和可控 Agent。它不是替代模型的算法，也不会自动补齐业务授权与外部副作用幂等。

## 366. 【推导】state schema 与 reducer 怎么设计？如何处理状态更新与合并？ {#q-366}

**参考答案：**

state schema 定义共享字段，节点通常返回部分更新；reducer 决定并发更新如何合并，例如消息追加或按 ID 更新。为每个字段明确覆盖/累加语义，避免重复重放产生重复消息和同键并发冲突。

## 367. 【推导】条件边与回边循环如何使用？如何构建 ReAct 式工具调用循环？ {#q-367}

**参考答案：**

模型节点产生 tool_calls 时条件边进入工具节点，工具执行后回边回到模型，无调用且验收满足时到 END。设置循环/步数限制、错误分支和取消检查，防止无限 ReAct 循环。

## 368. 【推导】checkpoint 与 thread_id 的语义是什么？如何关联持久化状态与任务执行？ {#q-368}

**参考答案：**

checkpointer 保存图状态快照，thread_id 是查找同一持久化执行线程/会话的配置标识，checkpoint_id 可定位具体历史点。它不是操作系统线程或天然授权凭据，业务上必须绑定租户与会话访问权。

## 369. 【推导】interrupt 与 HITL 如何实现暂停和恢复？图执行状态如何保存与继续？ {#q-369}

**参考答案：**

interrupt 在执行中产生待人工输入的暂停点，由持久化配置保存可恢复状态，再以对应 resume 命令继续。节点可能重执行，所以 interrupt 前副作用需幂等；审批绑定 run/版本并重新鉴权。

## 370. 【推导】subgraph 如何拆分？父子图 state 如何传递与映射？ {#q-370}

**参考答案：**

按独立职责和稳定输入输出划子图，共享 schema 可直接传递，差异较大时用包装节点映射。明确父子状态所有权、检查点与失败传播，避免把所有内部临时字段泄露到父状态。

## 371. 【推导】同一业务链路里，LangGraph 图编排和业务流程逻辑应该如何划分职责？ {#q-371}

**参考答案：**

图层管理步骤依赖、路由、等待和恢复，领域服务管理订单规则、数据库事务和权限。节点调用可测试的业务服务并返回状态变化，避免在图边里散落复杂业务判断和外部副作用。

## 372. 【推导】astream_events 产生的事件怎么映射到前端展示和生产环境的观测系统？ {#q-372}

**参考答案：**

将框架事件映射成稳定的业务 event type，附 runId、stepId、callId、seq 和版本，过滤内部调试字段。前端按业务协议渲染，观测系统用 trace/span 关联；不能把原始框架事件当长期公共契约。

## 373. 【推导】prebuilt 图与自定义 StateGraph 有什么区别？如何选择？ {#q-373}

**参考答案：**

预置图/高层 Agent 适合标准工具循环、快速验证；自定义 StateGraph 适合复杂分支、审批和精确恢复。先确认当前版本的预置入口和扩展点，不能为少量差异一开始就重写所有运行机制。

## 374. 【推导】LangGraph 生产部署中，compile、持久化和运行配置应该如何管理？ {#q-374}

**参考答案：**

应用启动时构建/compile 可复用图，checkpointer/store 使用受控持久化后端，run 配置携带身份、thread、预算与版本。不要每请求创建昂贵连接，限制同 thread 并发更新，并为 schema 迁移提供策略。

## 375. 【推导】Agent 框架和 Agent Harness 的区别是什么？分别承担哪些职责？ {#q-375}

**参考答案：**

框架提供模型/消息/图等编程抽象，Harness 提供运行控制、上下文、工具权限、事件、取消和交付环境。两者功能会重叠，可把框架嵌入 Harness，但应明确状态、重试和预算的唯一控制者。

## 376. 【推导】LangGraph 的图编排核心概念有哪些？节点、边、状态如何协作？ {#q-376}

**参考答案：**

节点接收 state 并返回更新，边决定执行顺序，条件边根据状态路由，reducer 合并更新。START/END 表示边界，检查点保存执行状态；图可以有循环，不能把所有 LangGraph 流程都称为 DAG。

## 377. 【推导】AutoGen 的对话式多 Agent 和 CrewAI 的任务协作模式有什么区别？ {#q-377}

**参考答案：**

AutoGen 常以可交互代理和消息协作为核心，CrewAI 常以角色、任务和 process 协作为入口。两者都持续演进且能力重叠，应比较具体版本的状态、恢复、观测与成本，而非只用口号划绝对边界。

## 378. 【推导】Graph 编排和 while-loop 手写 Agent 循环有什么区别？如何取舍？ {#q-378}

**参考答案：**

手写 while-loop 简单、可控，适合短任务；图编排显式表达分支/循环，便于检查点和可视化，但引入框架语义。比较恢复、测试和团队维护需求，不应只按节点数量决定。

## 379. 【推导】什么时候应该引入框架，什么时候应该直接使用 SDK 和业务代码？ {#q-379}

**参考答案：**

先明确是否需要复杂状态、持久化、中断、多模型和工具集成。需求简单直接 SDK 加业务服务更轻；引入框架前用真实用例测收益，并把领域工具和状态契约从框架适配层分离。

## 380. 【推导】从 LangChain 迁到 LangGraph，需要调整哪些执行流程和状态管理逻辑？ {#q-380}

**参考答案：**

从隐式 chain/执行器循环转为显式 state、节点、边与 reducer，重新设计工具结果关联、终止和错误分支。增加 checkpointer、thread 映射和中断恢复，迁移时用轨迹对比验证行为而非只测最终文本。

## 381. 【推导】框架里的 Memory 抽象和记忆系统有什么区别？如何与业务记忆服务衔接？ {#q-381}

**参考答案：**

框架 Memory 通常是上下文注入/存取抽象，业务记忆系统还需来源、更新、冲突、隐私、权限、删除和评测。可把业务记忆作为工具/store 适配进框架，事实所有权不能交给临时 messages 数组。

## 382. 【推导】Tool 定义在框架之间怎么保持可移植性，避免与单一框架过度耦合？ {#q-382}

**参考答案：**

把工具核心写成独立业务函数/API，schema 和结果用平台无关类型，框架层只做包装。标准化错误、幂等和权限上下文，用契约测试跨适配器验证；不要在业务函数内部依赖框架消息类。

## 383. 【推导】框架自带的 streaming 和生产环境 SSE 输出如何衔接？ {#q-383}

**参考答案：**

框架 streaming 在后端适配为稳定 SSE envelope，统一 runId、seq、类型、脱敏与持久化。网络层负责连接、鉴权和续传，业务状态由 Runner 管；客户端不能直接依赖框架内部 callback 名。

## 384. 【推导】如何用框架做本地 POC，又如何将其演进为可部署、可观测的生产系统？ {#q-384}

**参考答案：**

POC 用真实小样本验证任务价值，保留模型/工具/状态契约。生产逐步接入数据库、队列、授权、观测、预算、恢复和 CI 评测，容器化与灰度发布；不能把本地 notebook 直接包 HTTP 当完整生产系统。

## 385. 【推导】CrewAI hierarchical process 和其他任务协作流程有什么区别？如何选择？ {#q-385}

**参考答案：**

CrewAI hierarchical process 常由管理者协调代理分工与执行，sequential 按任务顺序推进。管理者适合动态分配但增加调用与不可预测性，稳定依赖优先显式流程；可用参数与限制按安装版本检查。

## 386. 【推导】框架选型面试里该展示什么，而不只是罗列框架名称和 API？ {#q-386}

**参考答案：**

展示业务约束、候选架构、一次失败恢复案例、评测数据、成本/延迟和取舍。能解释状态所有权、权限、幂等与升级策略，比背诵框架 API 更能证明生产设计能力。

## 387. 【推导】框架未来会被 Harness 吞没，还是与 Harness 分工协作？如何理解两者的发展关系？ {#q-387}

**参考答案：**

框架与 Harness 的边界会融合，不能确定预测谁取代谁。稳定分工是抽象与集成帮助开发，运行控制与业务契约保证执行；架构应通过可替换适配层减少对任何趋势的依赖。

## 388. 【推导】生产 incident：框架升级后 tool 调用异常，应该如何定位、止损与回滚？ {#q-388}

**参考答案：**

先冻结升级/回滚受影响流量，比较旧新版本、工具 schema、消息序列和最小复现。检查适配器、序列化、依赖兼容与严格输出变化，补契约回归后再灰度；不要靠放宽校验掩盖异常。
