# 后端服务与 API 设计

共 **15 题**，题号 **565–579**。 [返回分类总览](./)

> 答案用于面试复习与工程讨论；【推导】保留原文标记，表示题意依据不完整截图补全。实现细节请结合项目锁定的版本验证。

## 565. 【推导】Agent 产品的 run API 核心资源应该如何设计？ {#q-565}

**参考答案：**

核心资源可用 sessions、runs、messages、artifacts、approvals、events，POST 创建 run，GET 查询/订阅，动作端点处理 cancel/resume。创建返回 runId 和初始状态，长任务异步完成，输入/输出与错误需版本化。

## 566. 【推导】session 与 run 的 API 边界怎么划分？ {#q-566}

**参考答案：**

session 聚合对话、参与者和上下文生命周期；run 表示某次目标执行，有独立状态、预算、产物和事件。一个 session 可有多个 run，明确并发/消息归属规则，不能用会话 ID 代替执行 ID。

## 567. 【推导】API 层鉴权与 run 级授权怎么分工？ {#q-567}

**参考答案：**

API 层验证身份和粗粒度 scope，run 服务校验租户、所有者/共享规则与操作许可；工具执行还需资源级授权。后台 worker 代表原主体使用受限委派身份，不能因请求已登录而允许任意 runId。

## 568. 【推导】幂等键在 Agent run 与写操作 API 中如何设计和使用？ {#q-568}

**参考答案：**

创建 run 和外部写动作各有自己的幂等域，以主体/端点/键唯一约束并存参数 hash 与结果。重复同参返回原结果，同键异参冲突，设置合理保留期；超时后客户端重试必须复用键。

## 569. 【推导】文件上传 API 怎么设计，才能接入 RAG 和多模态处理流程？ {#q-569}

**参考答案：**

创建附件记录并返回短期上传地址，上传后校验大小、真实类型、hash、病毒与归属，再异步解析/OCR/索引。run 引用 ready 的 attachmentId，状态可查询，下载也鉴权；失败和孤立上传定期清理。

## 570. 【推导】SSE 端点放在 API 层还是 Harness 层？如何划分职责？ {#q-570}

**参考答案：**

通常 API/网关提供鉴权和传输端点，Harness 产生业务事件并持久化，流式网关负责订阅/续传。可在小系统同进程实现，但职责清晰，不能把连接断开当 Harness 执行失败。

## 571. 【推导】限流与配额 API 怎么按租户、用户和任务维度设计？ {#q-571}

**参考答案：**

按租户、用户、模型和任务类别设置请求速率、并发、token/费用配额，创建 run 可预留预算，执行时结算。返回稳定限流码与重试提示，公平队列避免大租户独占，关键检查在服务端原子执行。

## 572. 【推导】多租户 Agent API 如何实现数据隔离与访问控制？ {#q-572}

**参考答案：**

身份上下文派生可信 tenantId，所有查询、文件、索引、缓存和事件按租户授权，禁止相信客户端传入的归属字段。数据库可加行级安全，配合跨租户攻击测试与后台任务权限传播。

## 573. 【推导】Agent API 错误码体系怎么兼顾业务错误、模型错误和工具错误？ {#q-573}

**参考答案：**

统一 code、message、retryable、requestId/runId 与受控 details，区分输入、认证、权限、冲突、限流、依赖和内部错误。HTTP 状态表达传输层语义，业务终态另存 run；不能把内部堆栈/供应商凭据透出。

## 574. 【推导】resume 与 cancel API 的契约应该如何定义？如何处理并发和重复请求？ {#q-574}

**参考答案：**

resume 需 waiting 状态、输入 schema、审批权限和 expectedVersion；cancel 是幂等意图，返回已终态或取消中。通过原子状态转换处理并发，重复调用返回稳定结果，不让 resume 复活 cancelled run。

## 575. 【推导】Webhook 在 Agent 长任务里承担什么职责？如何保证通知可靠性？ {#q-575}

**参考答案：**

Webhook 通知长任务状态与产物，带事件 ID、版本、签名和时间戳。持久 outbox 后投递、有限退避、去重与死信，接收方快速确认；通常至少一次交付，不能承诺无条件 exactly-once。

## 576. 【推导】API 层与 Harness 工程的分界线在哪里？ {#q-576}

**参考答案：**

API 层管理外部契约、身份、请求校验、限流和响应，Harness 管执行循环、工具、上下文、状态推进与事件。领域服务处理业务事务；边界由契约连接，避免 API 请求 handler 内嵌整段长循环。

## 577. 【推导】Agent API 版本策略怎么支持 Web、移动端等不同客户端的兼容演进？ {#q-577}

**参考答案：**

优先兼容性新增，字段有默认语义，客户端忽略未知字段；破坏性变化使用新版本/能力协商和弃用期。事件 schema 也需版本化，发布前测试旧 Web/移动端，进行中的 run 固定兼容执行版本。

## 578. 【推导】BFF 在 Agent 产品里解决什么问题？什么时候需要引入？ {#q-578}

**参考答案：**

BFF 为不同客户端聚合数据、适配鉴权和视图形态，如移动端精简事件与产物摘要。多个客户端需求明显分化时有价值，单一简单应用可先不加；BFF 不应复制 Harness 状态机和领域规则。

## 579. 【推导】Demo 级 Agent API 上生产必须补齐哪些能力？ {#q-579}

**参考答案：**

补认证/授权、幂等、异步 run 状态、错误契约、限流配额、附件安全、事件续传和审计。加入版本兼容、观测、故障恢复与回归测试，再通过压测和灰度验证真实服务能力。
