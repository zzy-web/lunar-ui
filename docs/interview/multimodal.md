# 多模态 Agent

共 **15 题**，原始题号 **698–712**。 [返回分类总览](./)

> 答案用于面试复习与工程讨论；【推导】保留原文标记，表示题意依据不完整截图补全。实现细节请结合项目锁定的版本验证。

## 698. 【推导】原生多模态模型和流水线式多模态方案有什么区别？如何选择？ {#q-698}

**参考答案：**

原生多模态模型在统一模型内理解多种模态，跨模态关联方便；流水线由 OCR/ASR/视觉模型再接语言模型，组件可控且可替换。比较质量、定位证据、延迟、成本和隐私，复杂文档常采用混合方案。

## 699. 【推导】用户上传图片后，进入 Agent run 之前和执行期间需要经过哪些处理步骤？ {#q-699}

**参考答案：**

先验证身份、大小、真实 MIME 与恶意内容，存受控对象存储，生成附件 ID/短期访问凭证。按需压缩、OCR 或分块，run 只引用获授权文件，记录页码/坐标；结束后按保留策略清理，不把公网永久 URL 当安全方案。

## 700. 【推导】专用 OCR 和 vision 模型读取同一文档有什么差异？如何选择与组合？ {#q-700}

**参考答案：**

OCR 更适合逐字提取与坐标、版面结构，可校验文本；vision 擅长图表、语义和跨区域理解，但可能漏字/误读。常用 OCR 取文字、视觉解释布局，再对关键数字与原图复核，保留页码和框选来源。

## 701. 【推导】vision 类 tool 应拆多细？返回体应该包含哪些结果、定位和置信信息？ {#q-701}

**参考答案：**

按稳定业务能力划分，如 OCR 页面、检测控件、理解图表，避免只提供全能“看图”或过细像素操作。返回对象 ID、文本/类别、坐标系、页码/时间、置信与证据裁剪引用，错误和大小限制需统一。

## 702. 【推导】音频输入走流式还是批处理？ASR 与 Agent 执行流程如何衔接？ {#q-702}

**参考答案：**

实时语音用流式 ASR 降首响应，批处理适合录音分析和离线转写。区分 interim 与 final 文本，稳定片段才能触发有副作用动作，处理端点检测、说话人、打断与取消，保留音频时间戳。

## 703. 【推导】视频输入不能整段进入模型时，抽帧、切片和时间信息应该如何组织？ {#q-703}

**参考答案：**

按镜头变化、运动或时间间隔抽关键帧，音轨 ASR，片段与帧都携带原视频时间范围。先低分辨率检索再精读相关片段，避免均匀抽帧遗漏关键事件；结论引用时间点并说明采样限制。

## 704. 【推导】modality routing 由哪一层做？如何根据输入类型选择模型与工具？ {#q-704}

**参考答案：**

入口识别 MIME 和业务意图，编排层根据能力/权限/预算选择 OCR、ASR 或多模态模型。模型可建议路由，但文件安全检查和硬限制由程序负责，失败时允许受控降级而非无限重试。

## 705. 【推导】多模态上下文成本主要在哪些环节产生？如何控制 token、存储和处理成本？ {#q-705}

**参考答案：**

成本来自图像分辨率/块数、视频帧、音频时长、token、转码和存储。去重缓存、分层采样、按需 OCR/精读、限制附件大小和并发，用实际 usage 归因；压缩需验证不会损失关键证据。

## 706. 【推导】视觉 grounding 在产品里怎么落地？如何关联模型判断与图片或界面中的具体位置？ {#q-706}

**参考答案：**

把判断关联到明确图像 ID、分辨率、坐标框/点或 DOM 元素，UI 可高亮展示证据。执行前用最新截图/DOM 验证目标，处理缩放和滚动坐标变换；定位准确不代表动作已获授权。

## 707. 【推导】多模态附件在前端 Agent UI 应该如何展示、管理和关联执行结果？ {#q-707}

**参考答案：**

以附件卡展示名称、类型、上传/解析状态、预览与删除，结果标注对应文件/页码/时间。持久化 attachmentId 与 run/message 关联，失败可重试，访问链接短期授权；不要把二进制正文塞进消息状态。

## 708. 【推导】多模态输入的安全与合规边界有哪些？如何处理敏感内容和不可信指令？ {#q-708}

**参考答案：**

检查恶意文件、敏感/个人数据和跨租户访问，图片文字和音频转写中的指令仍是不可信内容。控制模型供应商传输、存储期限和输出暴露，高风险识别交人工；相关法律要求按地区和用途审核。

## 709. 【推导】怎么评测 vision Agent？别只用文字答案，还应该验证哪些视觉理解与操作能力？ {#q-709}

**参考答案：**

评测文字识别、表格/图表关系、空间定位、指代、坐标误差与任务动作成功率。加入低清、旋转、遮挡和诱导指令，要求证据框/页码可回查，同时记录延迟、成本与安全失败。

## 710. 【推导】同一轮图片、PDF、音频并存时，如何组织上下文和处理顺序？ {#q-710}

**参考答案：**

为所有附件建立统一 ID、类型、来源与页码/时间索引，先并行安全检查和基础解析，再按问题选择关联内容。跨模态关系通过明确引用建立，限制总预算并先处理依赖材料，不按上传顺序盲目全量灌入。

## 711. 【推导】多模态 tool 并行调用时怎么控制扇出、资源占用和结果合并？ {#q-711}

**参考答案：**

任务队列按 GPU/CPU/内存和供应商限额设置并发，单 run 限制 fan-out。结果以附件/页码/时间标识合并，超时允许部分产物并显式标缺失；同一文件解析可去重，不能无限创建重型任务。

## 712. 【推导】生产里多模态 Agent 常见翻车情况有哪些？如何定位和改进？ {#q-712}

**参考答案：**

常见有小字漏读、表格错列、坐标漂移、视频漏帧、ASR 错词和多附件混淆。保留处理版本及证据定位，分层评测解析/理解/执行，针对关键字段复核，而非只替换更大模型。
