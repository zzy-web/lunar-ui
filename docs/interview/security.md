# 权限、安全与合规

共 **15 题**，题号 **657–671**。 [返回分类总览](./)

## 657. 【推导】Agent 工具权限模型怎么设计？如何限制不同主体可调用的工具和参数范围？ {#q-657}

**参考答案：**

授权主体包括用户、租户、代理/worker 的委派身份，策略限制工具、资源和参数范围。工具执行前调用决策并绑定当前上下文，默认拒绝、最小权限，敏感操作绑定授权证据，不能靠模型声明角色。

## 658. 【推导】Prompt injection 在 Agent 场景中如何发生？如何防范与检测？ {#q-658}

**参考答案：**

不可信网页/文档/工具返回伪装成指令，诱使 Agent 改目标、泄露或越权。来源分级、上下文隔离、最小工具权限、参数/外发校验和风险审批形成纵深防护，检测只能辅助，需持续红队测试。

## 659. 多租户 Agent 隔离要做到哪几层？ {#q-659}

**参考答案：**

隔离身份授权、数据库/向量/对象、缓存与记忆、队列/执行环境、凭据/网络、日志/事件和配置扩展。每层都携带可信 tenantId 并验证归属，测试跨租户枚举/缓存命中，不能仅靠前端隐藏数据。

## 660. 【推导】Secrets 和 API Key 在 Agent 链路中如何保护，避免进入上下文或日志？ {#q-660}

**参考答案：**

秘密由密钥服务和工具代理管理，模型只接触最小业务参数，日志、错误、截图和工具输出统一脱敏。限制凭据作用域/期限与出站目的地，检测泄露后立即撤销轮换，避免扫描发现后仍继续执行。

## 661. 【推导】写操作为什么要 HITL？审批策略应该如何设计？ {#q-661}

**参考答案：**

人工介入用于不可逆、高风险、授权不明确或影响超出预期的写操作，并非所有写入都必须逐次审批。审批呈现具体对象、内容和影响，绑定参数/hash、版本、主体与期限，防止批准后内容被替换。

## 662. 【推导】Agent 审计日志要记什么？谁能访问，如何保证可追溯性？ {#q-662}

**参考答案：**

记主体/租户、run/call、工具/版本、目标、脱敏参数/结果摘要、授权与审批、时间、外部操作 ID。限制访问、加密、防篡改并按要求保留，记录自身访问；审计不可把密码/完整机密作为证据存入。

## 663. MCP 工具供应链风险怎么治理？ {#q-663}

**参考答案：**

审查发布者、包/镜像来源、依赖、工具描述与权限，固定版本和签名/校验，沙箱运行并限制网络/凭据。更新时检测 schema/描述变化与恶意行为，支持立即禁用/回滚，不信任“协议兼容”就等于安全。

## 664. 【推导】数据驻留与跨境合规对 Agent 架构有什么影响？ {#q-664}

**参考答案：**

影响模型/存储区域、日志与备份位置、支持人员访问、跨区复制和供应商选择。建立数据分类与流向清单，按具体地区/用途核对适用规则和合同，由合规专业人员审核；技术隔离不能单独证明法律合规。

## 665. 【推导】RBAC 在 Agent 产品里怎么落到用户、任务和工具操作上？ {#q-665}

**参考答案：**

角色映射到 run 创建/读取/取消、工具调用和资源范围，API 与工具端均验证用户/委派身份。RBAC 可结合租户、资源归属和金额等 ABAC 条件，角色修改及时影响长任务，默认拒绝未定义操作。

## 666. 【推导】沙箱执行外部代码或 Shell 时，边界应该如何设置？ {#q-666}

**参考答案：**

限制文件路径、进程、系统调用、网络、CPU/内存/时长和挂载，使用非特权容器/更强隔离执行不可信代码。凭据不放入可读环境，命令和参数分离，禁止任意宿主控制接口，记录产物并清理环境。

## 667. 【推导】红队测试 Agent 系统怎么组织和执行？ {#q-667}

**参考答案：**

明确授权范围和隔离环境，围绕注入、越权、秘密、供应链和副作用设计攻击矩阵。使用测试数据/账号、记录可复现轨迹和实际影响，分级修复并回归；生产演练须有停损与响应负责人。

## 668. 【推导】不可信内容（检索、网页、用户上传文件等）如何与可信指令隔离？ {#q-668}

**参考答案：**

可信指令来自受控配置/授权用户，不可信内容独立标来源、作用域与版本，只作为证据。即便使用分隔符，运行时仍校验工具/网络/参数，外部文本不能自行声明系统身份或扩大权限。

## 669. 【推导】租户间 prompt 与 memory 泄露如何防范、检测和处理？ {#q-669}

**参考答案：**

对 prompt 缓存、画像、向量、历史、工具结果和观测全链路带租户作用域；共享缓存不混入私有数据。跨租户 canary/攻击测试检测泄露，事件发生后隔离受影响资源、撤销访问、清理派生数据并调查。

## 670. 【推导】细粒度 policy（OPA 等）和 Harness 如何集成并执行权限决策？ {#q-670}

**参考答案：**

Harness 将主体、动作、资源、租户、参数与上下文送 policy engine，获得 allow/deny/需审批及义务。默认拒绝、策略版本可追踪，在工具执行前再次检查，缓存决策需短期且撤权可失效。

## 671. 【推导】安全事件响应：从告警到封禁 tool 的处理流程如何设计？ {#q-671}

**参考答案：**

告警后保全证据并评估范围，按严重度暂停 run/工具、撤销凭据和阻断外发，通知既定响应人员。核验已发生动作、补偿/恢复并修复策略与供应链，受控解禁，复盘转化为检测与回归测试。
