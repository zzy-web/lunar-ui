# Workflow 工作流编排

共 **15 题**，题号 **404–418**。 [返回分类总览](./)

> 答案用于面试复习与工程讨论，具体实现请结合项目锁定的版本验证。

## 404. Workflow 编排、Agent Loop、Planner 分别解决什么问题？它们如何配合？ {#q-404}

**参考答案：**

Workflow 决定稳定步骤与依赖，Planner 生成/调整任务方案，Agent Loop 在局部目标内选择动作。可由 Workflow 固定审批和验收，Planner 规划分析阶段，Loop 执行工具并回传状态，明确唯一终止控制者。

## 405. 状态机在 Agent 系统里应该描述什么？如何定义状态与转换条件？ {#q-405}

**参考答案：**

状态机描述 queued、running、waiting_input、succeeded、failed、cancelled 等生命周期及合法转换。每次转换带事件、条件、版本和操作者，终态防重复修改，暂停不等于失败，取消请求不等于已取消。

## 406. 确定性节点和 Agent 节点在混合工作流中如何分工与衔接？ {#q-406}

**参考答案：**

确定性节点处理校验、鉴权、事务、路由硬约束，Agent 节点处理语义理解和不确定搜索。节点输出通过 schema/业务规则验证再推进，异常、超时与人工介入都应显式建模。

## 407. 人工审批、表单补全这类 HITL 步骤应该如何接入工作流？ {#q-407}

**参考答案：**

创建持久化等待节点，保存表单/审批 schema、动作摘要、版本、审批人权限与期限。收到提交后验证并原子推进，重复提交返回已有结果；拒绝、过期和并发取消应有明确状态转换。

## 408. DAG 编排和有限状态机（FSM）有什么区别？如何选择？ {#q-408}

**参考答案：**

DAG 不含循环，适合批处理和依赖调度；FSM 强调状态与事件转换，可表达循环和长期等待。复杂系统可 DAG 管任务依赖、FSM 管每个任务生命周期，避免用一种模型硬套所有关系。

## 409. Workflow 的 checkpoint 和断点恢复怎么设计？ {#q-409}

**参考答案：**

在步骤可提交边界保存状态、输入版本、结果引用、已发外部操作与消息游标。重启从最近已确认状态恢复，并查询不确定操作；检查点要版本化、访问受控，恢复流程需定期演练。

## 410. 工作流步骤的幂等和重试策略怎么设计？如何避免重复副作用？ {#q-410}

**参考答案：**

每个逻辑步骤用稳定 operationId 和参数摘要保证幂等，瞬时失败有限退避重试，永久/权限失败直接分支处理。重试预算与总体 deadline 统一，不能层层重试放大流量。

## 411. 失败补偿（Saga / 回滚）在 Agent 工作流中如何实现？ {#q-411}

**参考答案：**

Saga 为每个已提交步骤定义业务补偿，如撤销预订，而非数据库级整体回滚。按反向依赖执行补偿并记录状态，补偿本身幂等且可失败；不可逆动作要提前确认或设计人工处置。

## 412. 事件驱动触发 workflow（Webhook 等）怎么设计？如何处理重复和乱序事件？ {#q-412}

**参考答案：**

Webhook 验签并检查时间窗口/重放，事件以唯一 ID 入持久队列，消费者去重。用实体版本处理乱序，缺少前置事件时缓冲或查询权威状态；响应接收成功与业务完成应分开。

## 413. 子工作流和嵌套 Agent 阶段怎么组合？如何传递输入、状态和执行结果？ {#q-413}

**参考答案：**

子工作流以稳定输入/输出契约调用，父流程保留 childRunId 与依赖，避免直接共享全部可变状态。定义超时、取消传播、错误与补偿边界，产物用引用传递并执行相同权限检查。

## 414. Workflow 版本升级时，运行中的实例如何迁移或保持兼容？ {#q-414}

**参考答案：**

新实例用新版本，运行中实例通常固定旧定义直到结束；必须迁移时提供显式状态映射和兼容工具/存储。先备份和验证可恢复性，不能热替换节点后假设旧检查点仍能执行。

## 415. Workflow state、业务单据 state 有什么区别？如何保持状态一致？ {#q-415}

**参考答案：**

Workflow state 表示执行进度，单据 state 表示领域事实，两者不能随意互相覆盖。业务变更在领域事务内完成，执行进度通过 outbox/事件关联并重试同步，定期对账修复中间失败。

## 416. 长运行 workflow 对用户怎么展示进度、等待状态和失败原因？ {#q-416}

**参考答案：**

展示当前阶段、已完成子目标、等待原因、可恢复错误与下一步入口；未知总量用阶段进度，不伪造百分比。前端可重新订阅并拉快照，长任务结果通过持久 run 页面查看。

## 417. 从 Demo 脚本、if-else 到生产 workflow，需要补齐哪些编排和运行保障能力？ {#q-417}

**参考答案：**

需要显式状态机、持久队列、步骤幂等、有限重试、超时取消、检查点、补偿和人工节点。加版本化、观测和故障注入测试，使进程崩溃/网络超时后仍可判断下一步。

## 418. 怎么评测 workflow 编排质量？应该关注哪些指标和测试场景？ {#q-418}

**参考答案：**

测端到端成功率、步骤耗时、等待占比、重试/补偿率和恢复时间。测试重复/乱序事件、进程崩溃、审批竞态、版本升级及外部写入状态不明，验证不丢任务、不重复副作用和能正确终止。
