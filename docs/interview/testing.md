# 自动化测试

共 **15 题**，题号 **613–627**。 [返回分类总览](./)

> 答案用于面试复习与工程讨论，具体实现请结合项目锁定的版本验证。

## 613. Agent 离线评测和在线评测各自解决什么问题？如何配合？ {#q-613}

**参考答案：**

离线评测在固定数据和环境中做回归/选型，在线评测观察真实分布、业务结果与漂移。先离线门禁再小流量上线，在线失败脱敏进入回归集，避免直接用用户流量验证危险操作。

## 614. golden traces 是什么？和 golden answers 有什么区别？ {#q-614}

**参考答案：**

golden answers 描述期望最终输出，golden traces 描述关键调用、状态和约束轨迹。Agent 可有多条正确路径，轨迹应约束必要/禁止行为及产物，而非逐 token 或严格复制唯一工具顺序。

## 615. 评测 rubric 怎么设计才可复现、可比较？ {#q-615}

**参考答案：**

rubric 明确质量维度、等级、可观测证据、正反例和判定边界，区分硬约束与软评分。人工标注校准一致性，固定版本与评测输入，模型裁判需盲评并抽样复核，不能只写“回答是否好”。

## 616. Agent 回归测试在 CI 里怎么跑？如何控制成本和结果波动？ {#q-616}

**参考答案：**

CI 先运行确定性单测/契约，再小型代表性模型回归，完整昂贵评测定时或发布前执行。固定模型/Prompt/工具版本并缓存可复用输入，多次采样报告区间和阈值，预算超限不能静默跳过关键门禁。

## 617. 人机评测（human eval）什么时候需要引入？如何组织评审与标注？ {#q-617}

**参考答案：**

高风险、主观质量、歧义和模型裁判分歧时需人工评测。使用脱敏任务、明确 rubric、盲评/双标与仲裁，报告一致性；把专家注意力集中在边界与失败，不能将少量偏好投票当全面质量证明。

## 618. Tool mock 与 stub 在评测里怎么用？如何保证测试代表真实行为？ {#q-618}

**参考答案：**

stub 提供预设结果，mock 还可验证调用参数/次数，适合稳定复现权限、超时和异常。另设沙箱集成检查真实 API/schema 漂移，定期从生产脱敏轨迹更新桩，避免只测永远成功的假工具。

## 619. 多轮对话脚本怎么写，才能覆盖真实任务、澄清和异常分支？ {#q-619}

**参考答案：**

脚本用状态机表达用户目标、可能澄清、确认/拒绝和环境变化，断言结果与允许副作用。覆盖取消、重复输入、缺信息、改意图和工具失败；固定关键条件，允许等价自然语言而非全文字符串匹配。

## 620. Agent 安全评测（越狱、越权、注入等）应该如何设计？ {#q-620}

**参考答案：**

在授权隔离环境测试直接/间接注入、越权、跨租户、秘密外传、危险参数和恶意工具返回。判定实际动作/泄露而不只看模型拒绝语句，记录覆盖与严重度，修复后加入回归。

## 621. CI 里面 Agent 评测的流水线架构怎么设计？ {#q-621}

**参考答案：**

流水线分静态/单测、工具契约、固定任务回归、安全测试与预发布 E2E，产出版本化报告。隔离凭据/数据并限制并发费用，质量/安全硬门禁独立于软评分，失败附 trace 便于定位。

## 622. 在线 A/B 和 shadow 评测 Agent 怎么做？如何控制对真实用户与业务的影响？ {#q-622}

**参考答案：**

A/B 将用户稳定随机分配到真实版本并衡量业务指标；shadow 复制输入但不影响用户。影子运行禁用真实写副作用、脱敏并计入预算，A/B 设置停损和公平分群，不能让两组重复执行业务动作。

## 623. 失败 taxonomy 怎么建？怎么驱动问题归因和持续改进？ {#q-623}

**参考答案：**

按理解、规划、检索、工具选择/参数、权限、执行、恢复和输出等分类，记录主因/次因与证据。聚合频率、影响和成本决定修复优先级，修复对应新增测试；标签需持续校准而不是全归“模型不行”。

## 624. LLM-as-judge 评测的利弊和落地注意事项有哪些？ {#q-624}

**参考答案：**

LLM 裁判可扩大量化语义质量，但有偏好、位置、长度和同模型偏置，也可能被答案注入。固定 rubric/版本、打乱顺序、提供证据并与人工校准，硬安全和数值正确性优先用确定性检查。

## 625. 检索与工具链评测要和 end-to-end 评测怎么配合？ {#q-625}

**参考答案：**

检索测召回与权限，工具测契约/幂等/失败，E2E 测业务目标与整体副作用。单层通过不保证整体成功，用同一 trace 分层归因；分层测试快且可定位，端到端验证集成与真实路径。

## 626. 评测环境与生产环境差异怎么控制？ {#q-626}

**参考答案：**

对齐依赖、模型、Prompt、schema、数据分布、权限和网络限制，使用脱敏快照和生产等价沙箱。记录不可复现差异并做小流量验证；测试环境工具全成功会掩盖限流、超时和版本漂移。

## 627. 评测指标怎么进入 Dashboard 和发布门禁？ {#q-627}

**参考答案：**

将评测结果按模型/Prompt/代码/数据版本入库，展示质量、成本、延迟和失败分布趋势。门禁设置硬安全阈值、质量下限与退化容忍，报告样本数/方差，灰度在线指标恶化自动暂停或回滚。
