# 任务推理策略

共 **15 题**，题号 **465–479**。 [返回分类总览](./)

> 答案用于面试复习与工程讨论；【推导】保留原文标记，表示题意依据不完整截图补全。实现细节请结合项目锁定的版本验证。

## 465. 【推导】规划型推理和反应型推理在 Agent 中有什么区别？分别适合哪些任务？ {#q-465}

**参考答案：**

规划型先分解目标与依赖，适合较长、可预见任务；反应型根据当前反馈选择下一动作，适合变化环境。实践常用粗计划加局部 ReAct，计划更新需保留完成证据与风险边界。

## 466. 【推导】任务分解（Task Decomposition）如何实现？如何确定子任务的粒度和依赖关系？ {#q-466}

**参考答案：**

按可独立验收的结果拆分子任务，每项明确输入、输出、依赖和权限；粒度以可恢复、可测且通信成本可控为准。确定可并行部分，避免把不可分事务切开或拆成无意义微步骤。

## 467. 【推导】Plan 在工程里应该长成什么数据结构？如何表示步骤、依赖和完成状态？ {#q-467}

**参考答案：**

Plan 可用 steps 数组/DAG 表示，每项含 id、goal、dependsOn、status、owner、inputs、outputs、acceptance 与预算。记录版本、修改原因和证据引用，状态由执行事件更新，不能只维护自然语言列表。

## 468. 【推导】Chain-of-Thought、ReAct 推理方式有什么区别？如何用于 Agent 执行循环？ {#q-468}

**参考答案：**

CoT 强调中间推断步骤，ReAct 交替推理、动作与观察，使工具反馈影响后续决策。运行时保存可见计划和执行证据即可，不要求公开隐藏思维链；每轮动作仍需授权、验证和停止条件。

## 469. 【推导】Tree of Thoughts、多路径探索有什么作用？如何控制搜索范围和推理成本？ {#q-469}

**参考答案：**

Tree of Thoughts 把多个候选思路作为搜索树，通过评价选择扩展，可能提升复杂探索任务但增加计算。限制宽度、深度和总预算，用独立可检验目标评分并剪枝，不让模型自评形成无限自证。

## 470. 【推导】计划生成后要不要让人审？哪些任务或步骤需要人工确认？ {#q-470}

**参考答案：**

涉及权限扩大、不可逆操作、大额成本或关键业务选择的计划需要适当审核；低风险读任务可按既有授权执行。审批应针对具体动作和影响，而非一份笼统计划自动授权所有未来变化。

## 471. 【推导】计划过时（Replan）的触发条件有哪些？如何更新计划并衔接已完成的步骤？ {#q-471}

**参考答案：**

新证据否定假设、工具不可用、依赖失败、约束变化或预算不足时触发重规划。保留已完成步骤与副作用，生成新版本剩余计划并检查依赖，必要时对风险变化重新授权。

## 472. 【推导】子目标追踪和进度 state 怎么设计？如何识别阻塞和偏离目标的情况？ {#q-472}

**参考答案：**

每个子目标保存状态、验收、证据、阻塞原因和最后进展时间；通过事件更新并检测长时间无推进、重复动作和目标偏离。阻塞与失败分开处理，不能仅凭模型文本声称完成。

## 473. 【推导】推理预算（步数、token、工具调用次数等）如何分配和限制？ {#q-473}

**参考答案：**

设置 run 总步数、token、调用数、时间和费用上限，再按阶段划预算，关键校验预留余量。运行时实时扣减并在超限前总结/降级，子代理预算计入主任务，避免层层独立配额放大总成本。

## 474. 【推导】强模型规划、弱模型执行时，上下文和任务契约应该如何传递？ {#q-474}

**参考答案：**

强模型输出结构化步骤、必要事实/来源、权限、可调用工具、验收和失败升级条件，弱模型只处理限定子任务。回传证据后由校验器/主控验收，不通过则受控升级；不能把完整机密上下文无条件下发。

## 475. 【推导】Self-Reflection、Critic 层怎么设计？如何验证其收益并避免无效循环？ {#q-475}

**参考答案：**

Critic 根据独立 rubric、证据和测试检查产物，提出可执行修正，最多有限轮。通过消融对比成功率和成本证明收益，同一模型反复自我肯定不是独立验证，检查应优先用工具与确定性断言。

## 476. 【推导】开放域 Agent 怎么定义完成条件？如何判断任务已完成、应停止或需要澄清？ {#q-476}

**参考答案：**

将开放需求转成可观察产物和验收清单，区分完成、部分完成、阻塞和预算耗尽。结果由来源/测试/用户约束验证，必要输入缺失时澄清；不要把“没有下一工具调用”视作目标必定完成。

## 477. 【推导】多步推理里的未验证假设怎么管理？如何记录、验证并避免错误累积？ {#q-477}

**参考答案：**

建立假设列表，记录内容、来源、置信/确认状态、影响与验证动作，关键假设在有副作用前验证。依赖失败时使相关结论失效，摘要明确保留未知，避免假设经过多轮转述变成事实。

## 478. 【推导】怎么评测规划与推理质量？不只看最终结果，还应该评估哪些过程指标？ {#q-478}

**参考答案：**

评估计划覆盖、依赖正确性、工具有效率、无效步骤、重规划次数、预算遵守和证据追踪。结合最终任务成功，注入错误工具结果和环境变化测恢复；更长的推理文本不代表更高质量。

## 479. 【推导】从 Demo 单轮 ReAct 到可上线规划系统，需要补齐哪些能力？ {#q-479}

**参考答案：**

补结构化计划/状态、受控工具、预算与终止、证据验证、检查点恢复、幂等和人工节点。建立基线评测与可观测事件，先证明少量步骤可可靠运行，再增加多路径搜索或多 Agent。
