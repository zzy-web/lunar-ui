# Coding Agent

## 713. 【推导】代码 Agent 和通用聊天 Agent 的核心区别是什么？ {#q-713}

**参考答案：**

代码 Agent 需要理解仓库、修改文件并通过构建/测试验证，真实产物是可审查 diff 和证据。与聊天相比，它还需文件/终端权限、沙箱、版本控制、依赖管理、取消与失败恢复。

## 714. 【推导】主流 Agent 工具、Agent 框架和 Agent 平台之间有什么区别？如何比较？ {#q-714}

**参考答案：**

工具/产品提供用户工作入口，框架提供编程抽象，平台提供部署、租户、治理与共享运行能力，边界可能重叠。按任务完成率、集成、权限、可观测性和成本比较，而不是只比模型名称。

## 715. 【推导】Cursor 的产品形态和工程能力边界是什么？如何判断其适用场景？ {#q-715}

**参考答案：**

Cursor 属于集成代码上下文、编辑与 Agent 工作流的开发工具，适合在仓库内阅读和修改代码。具体索引、模式、权限和团队特性依版本/套餐变化，应以实际配置验证；它不能代替测试和代码审查。

## 716. 【推导】Claude Code 和 IDE 内 Agent 在交互方式、上下文获取和执行流程上有什么区别？ {#q-716}

**参考答案：**

CLI Agent 常围绕终端、文件与命令循环，IDE 内 Agent 更容易结合选区、诊断、符号和编辑器 UI。两者都可具备工具和上下文检索，差异以具体版本与工作流为准，不应绝对认为一方没有另一方能力。

## 717. 【推导】OpenAI Codex 类 coding agent 的典型架构与工作流程是什么？ {#q-717}

**参考答案：**

典型 Codex 类架构由客户端、Harness、模型、上下文构建和受控工具组成：理解任务→检索仓库→修改→运行验证→交付 diff。Harness 协调会话、循环、工具与流式事件，业务/产品仍需自己的控制。[OpenAI 官方说明](https://developers.openai.com/blog/codex-as-a-platform)

## 718. 【推导】Trae 等国产 AI IDE 的共同架构模式有哪些？如何理解其能力与差异？ {#q-718}

**参考答案：**

AI IDE 通常共享编辑器、仓库索引、模型网关、工具执行和 Agent 编排等模块。比较具体产品需验证代码理解、改动验证、扩展、隐私、权限与价格，不能仅由国产/海外标签推断能力或数据边界。

## 719. 【推导】这些工具里的 Rules、Skills、MCP 分别承担什么职责，如何配合？ {#q-719}

**参考答案：**

Rules 提供持续项目约束，Skills 提供按需任务方法，MCP 提供外部工具/资源连接。组合时先明确用户目标与规则，再加载匹配 Skill 并调用获授权能力；它们都不能绕过运行时权限。

## 720. 【推导】@文件、codebase 索引、选区等上下文入口如何工作？分别适合哪些场景？ {#q-720}

**参考答案：**

@文件提供精确指定上下文，选区聚焦局部问题，codebase 索引通过语义/关键词/符号召回相关代码。关键修改前仍读取真实文件确认版本，索引可能过期，检索片段不等于完整调用链。

## 721. 【推导】Agent 模式、Ask 模式、自动改代码模式有什么区别？如何控制执行边界？ {#q-721}

**参考答案：**

Ask 常偏解释与建议，Agent 常有多步工具执行，自动修改模式偏直接编辑，但产品命名不统一。实际边界由读写/终端/网络权限、确认策略和任务授权决定，应明确能做什么而非只看模式名。

## 722. 【推导】主流工具的终端、网络、写文件权限如何管理？如何限制操作范围？ {#q-722}

**参考答案：**

通过工作目录限制、文件白名单、网络目的地、命令策略、操作系统沙箱和最小权限凭据约束。对高风险操作按范围确认并审计；工具可用不意味着当前任务有权使用，审批设置也不是隔离的替代品。

## 723. 【推导】团队怎么统一 Rules、MCP 和模型配置，保证协作一致性？ {#q-723}

**参考答案：**

在版本库保存共享规则和工具配置模板，密钥由组织秘密管理注入，个人覆盖有明确优先级。固定模型/工具版本范围，CI 验证配置、权限与契约，变更审查并灰度，避免把机密提交到仓库。

## 724. 【推导】主流工具怎么接入 PR、CI 和 Code Review 流程？ {#q-724}

**参考答案：**

在隔离分支/worktree 生成 diff、运行 lint/test，再创建可审查 PR，CI 和人审通过后按团队流程合并。评论关联文件/行与证据，机器人用最小仓库权限，不能执行不可信 PR 中代码时同时暴露高权凭据。

## 725. 【推导】生产环境 Agent 平台的容量规划怎么做？如何估算并发、资源和模型调用需求？ {#q-725}

**参考答案：**

以到达率 λ、平均任务时间 W 估算并发 L≈λW，再叠加峰值和重试余量。分别预算模型 token/s、请求额度、工具连接、CPU/内存与队列，使用负载测试验证 P95 和每租户公平性。

## 726. 【推导】repo context 怎么采集？全量灌入和按需检索如何取舍？ {#q-726}

**参考答案：**

采集目录、配置、入口、符号与依赖关系，按问题用 rg、语言服务和语义检索定位，再读取关键文件。小仓库可较完整载入，大仓库按需获取并追踪来源版本，避免上下文被依赖产物和无关文件占满。

## 727. 【推导】apply_patch 和 diff 应该怎么做，才能让修改准确、可审查并可恢复？ {#q-727}

**参考答案：**

先读取当前文件并基于准确上下文生成最小 patch，应用前检查版本与周边内容，应用后看 diff 并运行相关验证。隔离并发编辑，保留 Git 恢复点，不覆盖用户未提交修改；失败不要盲目强制整文件替换。

## 728. 【推导】测试闭环在代码 Agent loop 里怎么设计？如何根据失败结果继续修复？ {#q-728}

**参考答案：**

根据改动选择相关静态检查/单测/集成测试，失败后分析日志、定位原因、最小修复再复测。限定迭代和预算，区分环境与代码失败，不能删测试或放宽断言来“通过”；最终报告真实验证范围。

## 729. 【推导】IDE 集成代码 Agent，前端和后端如何划分职责并同步执行状态？ {#q-729}

**参考答案：**

前端负责输入、diff/审批、流式展示和用户控制，后端负责模型循环、授权、工具、状态与事件。通过版本化 run API 和可续传事件同步，浏览器刷新后可恢复快照，客户端不是执行状态权威源。

## 730. 【推导】代码 Agent 的 sandbox 应隔离哪些资源与操作？如何兼顾可用性和安全？ {#q-730}

**参考答案：**

隔离文件、进程、网络、CPU/内存、凭据和宿主接口，默认无高权容器/宿主挂载。按任务发短期最小权限能力，限制出站目的地与资源，构建依赖同样不可信；可用性通过明确白名单而非全面放开实现。

## 731. 【推导】代码 Agent 走 PR 工作流，和直接修改或提交代码相比有什么取舍？ {#q-731}

**参考答案：**

PR 工作流有 diff、人审、CI 和可追溯历史，适合团队/生产；直接修改适合本地快速迭代但仍需验证与回退。选择取决于风险和协作要求，commit 本身不证明正确，推送/合并应遵循授权。

## 732. 【推导】lint 和 test gate 怎么卡进 Agent 执行流程，保证交付质量？ {#q-732}

**参考答案：**

在编辑后执行相关 lint/typecheck/test，提交或发布前设置明确质量门禁，CI 再做独立校验。失败需可定位且允许受控重试，记录测试命令和版本；禁止为了通过门禁自动删除检查。

## 733. 【推导】超大代码库检索中，语义搜索和符号检索如何配合？ {#q-733}

**参考答案：**

语义检索找概念和相似逻辑，符号检索定位定义、引用、类型和调用关系，关键词搜索补精确错误码。先召回后用真实文件和语言服务验证，索引绑定 commit，排除生成/依赖目录降低噪声。

## 734. 【推导】怎么防止代码 Agent 泄露 secret、凭据和其他敏感信息？ {#q-734}

**参考答案：**

凭据由运行时代理注入工具，模型只见必要标识；环境、日志和工具输出脱敏，限制文件/网络与外发。执行前后做 secret 扫描，避免将 .env、令牌或私有代码发向未授权端点；泄露后需撤销轮换。

## 735. 【推导】人工 code review 在 Agent 流程中应该放在哪里，如何提供足够的审查证据？ {#q-735}

**参考答案：**

在有副作用交付前审核需求符合性、diff、关键设计和验证证据，安全/业务关键路径加强人工检查。提供变更原因、测试、风险和未覆盖项，人审集中判断模型难验证的问题，不替代自动化门禁。

## 736. 【推导】代码 Agent 改多文件特性时，规划、执行和验证应该如何组织？ {#q-736}

**参考答案：**

先定位影响面与公共契约，规划互相依赖文件，分小步修改并保持中间可构建。隔离并发写入，每阶段检查 diff/类型和相关测试，最后验证跨模块行为；产物说明配置迁移和兼容影响。

## 737. 【推导】代码 Agent 如何读 CI 失败并修复？如何区分代码问题、环境问题和偶发失败？ {#q-737}

**参考答案：**

读取 CI job、日志、环境和改动范围，先复现首个根因；区分断言/编译失败、依赖/权限环境问题和已证实 flaky。修复后复跑受影响检查，偶发重试要有证据和上限，不能无限重跑直到绿灯。

## 738. 代码 Agent 的权限模型怎么设？ {#q-738}

**参考答案：**

身份映射到仓库、分支、文件、命令、网络和外部工具范围，区分读取、编辑、执行、发布与管理员能力。短期令牌、最小权限与风险确认结合，委派和子进程不得扩大授权，所有关键动作可审计。

## 739. 代码 Agent 典型事故与调试顺序？ {#q-739}

**参考答案：**

事故常有误删/覆盖、未授权外发、错误依赖、测试遗漏与重复提交。先暂停副作用、保全日志和 diff，再按输入/授权→上下文→模型决策→工具→验证定位，撤销凭据或回滚后补回归用例。
