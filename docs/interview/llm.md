# LLM 推理机制

共 **23 题**，题号 **217–239**。 [返回分类总览](./)

> 答案用于面试复习与工程讨论，具体实现请结合项目锁定的版本验证。

## 217. 大模型自回归生成（Autoregressive Generation）是什么？如何逐个生成 Token？ {#q-217}

**参考答案：**

自回归生成每步根据已有上下文预测下一个 token 的概率分布，采样后追加到序列，再继续预测，直到结束标记或预算耗尽。prefill 处理输入，decode 逐步生成；生成合理文本不代表事实已验证。

## 218. Token 和 Context Window 有什么区别与联系？ {#q-218}

**参考答案：**

Token 是模型处理的离散单位，可能是词片段、字符或其他编码；Context Window 是单次可处理的序列容量。输入历史、工具定义/结果以及输出预算都可能占用容量，具体计数取决于模型与 API。

## 219. 大模型的核心原理是什么？ {#q-219}

**参考答案：**

典型 LLM 把 token 映射为向量，经 Transformer 注意力与前馈层计算，输出后续 token 分布，通过大规模预测训练学习统计规律，再做后训练。它不是查询事实数据库，能力与错误都依赖数据、架构、训练和推理策略。

## 220. Token 是什么？为什么大模型一般使用 Token 作为文本处理单位？ {#q-220}

**参考答案：**

Token 是分词器词表中的单位，可在字符覆盖能力与序列长度之间折中。常见词可合并，罕见词拆成片段，不同语言的字符/token 比不同；不能用固定“一个词等于一个 token”估算所有输入。

## 221. Token 是怎么切出来的？为何同样的文本在不同模型中可能得到不同的 Token 数量？ {#q-221}

**参考答案：**

常用 BPE、Unigram 或字节级分词，依据各自词表和合并规则编码。不同模型训练数据、词表、规范化和特殊 token 不同，因此同一文本计数不同；预算应使用目标模型分词器或官方计数接口。

## 222. Agent 场景下 temperature、top_p 等采样参数分别有什么作用？如何选择？ {#q-222}

**参考答案：**

temperature 调整分布尖锐程度，top_p 限制累计概率候选集合。工具选择与结构化抽取通常追求稳定，创作可增加多样性；先调一个参数并用任务集验证，低温也不保证确定性或正确性，部分推理模型不支持这些参数。

## 223. 模型 API 中的 System / User / Assistant 消息分别有什么作用？ {#q-223}

**参考答案：**

System 常承载系统级规则，User 表达用户请求，Assistant 表示模型历史回复或工具调用。部分 API 另有 developer/tool 角色；不要把检索文本伪装为高优先级消息，角色优先级和可用字段以具体平台契约为准。

## 224. Pretrain、SFT、RLHF/DPO 分别是什么？它们对模型能力与行为有什么影响？ {#q-224}

**参考答案：**

Pretrain 从大规模数据学习语言与知识，SFT 用示范学习遵循任务，RLHF 用偏好奖励及强化学习调整行为，DPO 直接利用偏好对优化目标。后训练改善可用性和对齐，但不能保证无幻觉或所有任务都更强。

## 225. 大模型幻觉是怎么产生的？Agent 场景下如何识别和减少幻觉？ {#q-225}

**参考答案：**

幻觉可能来自知识缺失、错误检索、模糊指令、分布外输入和生成目标偏向看似合理的续写。通过可追溯检索、实时工具、来源交叉验证和允许拒答降低风险；最终结果需验证，不能仅让模型自报置信度。

## 226. Chain-of-Thought 和 Reasoning 有什么区别与联系？ {#q-226}

**参考答案：**

Chain-of-Thought 是把问题拆为中间步骤的一类推理/提示方式；Reasoning 指更广的推断能力或专门推理模型。可要求简明依据、可检验步骤和结论，不需要展示隐藏内部思维链；步骤看似连贯也可能错误。

## 227. Agent 场景下 Long Context 和 RAG 如何选择与配合使用？ {#q-227}

**参考答案：**

长上下文适合一次处理相关材料且避免检索遗漏，RAG 适合大规模、频繁更新和需权限过滤的知识。可先检索再把完整相关章节放入长上下文；比较召回、证据定位、延迟与成本，窗口大不保证有效利用全部信息。

## 228. KV Cache 是什么？它和 Agent 的多轮调用及推理效率有什么关系？ {#q-228}

**参考答案：**

KV Cache 保存注意力中已处理 token 的 key/value，解码时复用以减少重复计算，代价是显存。多轮能否复用受前缀、会话调度和平台实现影响；它不是用户长期记忆，也不意味着所有 API 调用共享缓存。

## 229. Structured Output / JSON Mode 有什么区别？如何用于 Agent 的结构化输出？ {#q-229}

**参考答案：**

JSON Mode 通常保证有效 JSON，Structured Output 可在支持范围内约束 JSON Schema。两者都不能保证业务事实正确；解析后仍校验字段语义、权限和拒答/截断情况，工具执行前必须完整验证参数。

## 230. Agent 技术栈里，Embedding 模型承担什么角色？有哪些典型使用场景？ {#q-230}

**参考答案：**

Embedding 把文本/图片等映射为向量，用距离近似语义相关性，常用于检索、去重、聚类和记忆召回。相似度不是事实正确率，需匹配距离函数、模型版本和业务评测，并结合关键词和权限过滤。

## 231. 多轮对话里模型为什么会“越聊越忘”？如何管理历史消息和上下文？ {#q-231}

**参考答案：**

历史可能超出窗口被裁剪，重要细节被噪声淹没，摘要丢失信息或旧事实失效。保存结构化任务状态与来源，按相关性检索历史，摘要保留约束/决策/待办，为当前问题和输出预留预算。

## 232. Prefix / Prompt Caching 能省多少成本和延迟？如何组织请求以提高缓存复用率？ {#q-232}

**参考答案：**

缓存收益由可缓存输入比例、命中率、计费规则和负载共同决定，没有统一百分比。把稳定系统说明/工具定义放在前面，动态内容放后面，保持前缀一致；通过真实 usage、命中率和延迟测量，并遵守租户隔离。

## 233. 模型量化（INT8 / INT4）对 Agent 的响应速度、资源占用和任务效果有什么影响？ {#q-233}

**参考答案：**

低比特量化降低权重内存与带宽需求，但速度取决于硬件内核、批量与是否需要反量化，不保证总是更快。可能损伤精度、工具选择和长上下文表现，需在目标设备上比较任务成功率、吞吐与尾延迟。

## 234. 如何给 Agent 主循环选模型？怎么权衡能力、成本和延迟？ {#q-234}

**参考答案：**

先列任务成功、工具调用、上下文长度、语言/模态和安全要求，用代表性任务集测准确率、P95 延迟与每次成功任务成本。按需采用小模型处理简单步骤、强模型兜底；不只看通用榜单。

## 235. Reasoning 模型的 thinking token 是什么？它对推理效果、成本和延迟有什么影响？ {#q-235}

**参考答案：**

部分推理模型在最终输出前使用内部 reasoning token，可能改善复杂任务但增加计算、时间和计费用量。可见回复通常不包含全部内部 token，预算与可调参数依模型而异；用效果—延迟曲线选择推理强度。

## 236. Agent 循环里 stop sequences 有什么作用？如何设置停止条件？ {#q-236}

**参考答案：**

stop sequences 在生成匹配文本片段时截断输出，适合文本边界，但模型/模式可能不支持。Agent 结束还需由程序验证目标、工具调用状态及步数/时间/成本上限；不能只依赖模型输出某个结束词。

## 237. 大小模型路由在 Agent 架构里怎么设计？如何决定任务交给哪个模型？ {#q-237}

**参考答案：**

先用规则或轻量分类评估任务复杂度、风险、所需模态与上下文，再路由模型，失败后受控升级。设置滞回和总预算，记录路由结果与真实任务收益；不能在低权限/隐私场景把数据无条件发给备用供应商。

## 238. 怎么判断一个模型是否适合当前 Agent 任务？需要评估哪些能力与指标？ {#q-238}

**参考答案：**

评估业务成功率、工具参数正确率、证据忠实度、结构化输出、长上下文、鲁棒性、权限遵守和取消能力，同时统计成本与 P50/P95 延迟。用真实任务、困难负例和固定版本对比，报告方差而非单个平均分。

## 239. 流式输出里，“模型侧 token 流”和用户实际看到的输出流有什么区别？如何处理？ {#q-239}

**参考答案：**

模型输出包含文本增量、工具参数增量和内部/控制事件，用户界面只应展示适合公开的内容。服务端先规范化为带 runId/序号/类型的业务事件，脱敏并校验，再增量渲染；网络分块不等于完整 token 或完整 JSON。
