# Agent Harness 工程

共 **14 题**，题号 **536–549**。 [返回分类总览](./)

> 答案用于面试复习与工程讨论；【推导】保留原文标记，表示题意依据不完整截图补全。实现细节请结合项目锁定的版本验证。

## 536. 【推导】Agent Harness 是什么？和框架有什么区别？ {#q-536}

**参考答案：**

Harness 是包围模型的执行系统，管理循环、上下文、工具、安全、状态和事件；框架提供构建这些能力的抽象与组件。两者可重叠，关键是明确谁拥有运行控制和事实状态，而不是给组件换名称。

## 537. 【推导】Harness 在整体架构里通常接在哪一层？如何连接模型、工具和业务系统？ {#q-537}

**参考答案：**

Harness 位于产品/API 与模型/工具之间，接受任务契约与身份，调用模型和受控工具，持久化执行并发送事件。领域服务负责业务规则与事务，Harness 不应直接替代所有业务系统。

## 538. 【推导】Harness 里的 Agent Loop 谁来控制？如何管理继续执行、暂停和结束？ {#q-538}

**参考答案：**

循环由 Runner/调度器控制，模型提供下一动作建议，程序检查状态、授权、预算和取消。等待输入时持久暂停，终止由验收/失败/取消/超限规则决定，不能让模型无限调用直到自行结束。

## 539. 【推导】Tool Runtime 在 Harness 里要管理哪些职责？如何控制权限、并发和调用生命周期？ {#q-539}

**参考答案：**

Tool Runtime 负责注册/发现、schema 与权限校验、执行、超时、取消、并发限额、幂等、重试和日志。输入结果都脱敏/限大小，工具版本与 run 关联；外部操作状态不明时先核验再恢复。

## 540. 【推导】Context Builder 在 Harness 里负责什么？如何组装与裁剪上下文？ {#q-540}

**参考答案：**

Context Builder 收集可信规则、任务状态、近期消息、必要记忆和检索证据，按来源与优先级组装。计算 token 预算并裁剪低价值内容，保留工具协议配对与关键约束，不承担实际授权决策。

## 541. 【推导】Harness 对外事件模型怎么设计？如何支持流式展示、观测和回放？ {#q-541}

**参考答案：**

设计统一事件 envelope，包括 eventId、runId、step/callId、seq、type、schemaVersion、timestamp 和 payload。关键状态先持久化再发布，支持续传、去重、脱敏与终态事件；前端与观测消费同一稳定语义。

## 542. 【推导】Harness 配置（policy profile）应该包含哪些策略，如何应用到不同任务？ {#q-542}

**参考答案：**

policy profile 包含工具/资源/网络范围、风险审批、并发、重试、token/费用/时间预算和数据保留策略。配置版本绑定 run，由执行端强制检查，用户输入不能自行扩权；不同租户/任务可选受控模板。

## 543. 【推导】本地 Harness（IDE/CLI）和云端 Harness 有什么差异？如何复用核心能力？ {#q-543}

**参考答案：**

本地更贴近文件/终端和用户交互，云端强调多租户、队列调度、隔离与弹性。复用状态机、协议、工具契约和策略核心，通过文件系统/沙箱/存储适配器区别实现，不假设本地凭据可直接搬云。

## 544. 【推导】Harness 如何接入 MCP、Skill 等扩展能力？如何管理发现、加载和权限？ {#q-544}

**参考答案：**

MCP 适配器发现并连接外部能力，Skill 加载器按任务读取说明和资源，再由同一工具运行时执行。目录与加载受租户/来源控制，版本、权限和脚本审查独立实施，不能因扩展来自目录就默认可信。

## 545. 【推导】Harness 的会话、取消、超时怎么设计？如何管理执行生命周期？ {#q-545}

**参考答案：**

session 管会话上下文，run 管一次执行，取消为显式状态请求并向模型/工具传播信号。统一 deadline，持久化 waiting/terminal 状态和事件，处理取消与完成竞态；超时不自动撤销已提交副作用。

## 546. 【推导】怎么测试 Harness？和只测模型输出相比，还需要验证哪些执行与控制行为？ {#q-546}

**参考答案：**

除输出质量，还测状态转换、权限拒绝、预算、取消、超时、幂等、检查点恢复、事件顺序和租户隔离。用假模型/工具做确定性测试，再集成故障注入与真实任务评测，验证未执行禁止动作。

## 547. 【推导】Harness 和 Agent 框架（LangGraph 等）如何分工与集成？ {#q-547}

**参考答案：**

可让 LangGraph 处理图与检查点，Harness 处理身份、策略、工具环境、对外事件和预算。明确谁负责循环、重试、取消和状态持久化，避免双重重试与双份事实状态。

## 548. 【推导】从脚本循环到 Harness，最小可用版本应该包含哪些能力？ {#q-548}

**参考答案：**

最小版需要任务输入、模型适配、工具注册/校验、有限循环、结构化状态、事件、错误处理和停止预算。若已有写工具，即便 MVP 也必须有权限与幂等；可先单进程但状态格式应为恢复预留空间。

## 549. 【推导】生产级 Harness 还要补哪些非功能能力？如何考虑可靠性、扩展性和安全性？ {#q-549}

**参考答案：**

补齐可靠持久化、调度公平性、资源隔离、恢复/灾备、观测、评测、发布回滚与安全审计。用 SLO 和容量测试确定瓶颈，非功能能力需要故障演练验证，不能仅写在架构图上。
