# 工程化部署

共 **14 题**，题号 **643–656**。 [返回分类总览](./)

> 答案用于面试复习与工程讨论，具体实现请结合项目锁定的版本验证。

## 643. Agent 服务在 K8s 上怎么部署？如何划分 API、Worker 和状态存储？ {#q-643}

**参考答案：**

API 负责认证/创建 run，Worker 从持久队列执行 Harness，数据库/对象存储保存状态与产物，流网关分发事件。分别 Deployment 与弹性策略，设置资源请求/限制、探针和网络策略，状态服务要备份与高可用。

## 644. Worker 水平扩展时，如何避免重复执行和状态冲突？ {#q-644}

**参考答案：**

队列按至少一次投递设计，Worker 用租约/心跳领取，状态更新用版本条件和 fencing token 防旧持有者提交。外部写动作使用幂等键，重启先核验结果；分布式锁本身不能保证外部副作用只发生一次。

## 645. Checkpoint 存哪里？S3、PostgreSQL 等方案如何选择？ {#q-645}

**参考答案：**

PostgreSQL 适合事务、索引查询和小型状态原子更新；S3 类对象存储适合大快照/附件且成本较低，但无同等事务查询。常用数据库保存游标/元数据、对象存储存大内容与 hash，设计一致提交和清理。

## 646. 蓝绿发布和金丝雀发布中，Agent 服务如何处理进行中的 run 与状态兼容？ {#q-646}

**参考答案：**

新 run 路由新版本，旧 Worker 排空既有任务；检查点、事件和工具契约保持兼容。金丝雀先小流量观测，回滚时明确谁接续旧状态；数据库变更用 expand-contract，不能切回代码就假设数据恢复。

## 647. Secrets 和 API Key 在 Agent 产品里如何存储、注入与轮换？ {#q-647}

**参考答案：**

用密钥管理服务/KMS 存储，运行时按工作负载身份获取短期凭据，模型仅获得必要能力引用。按租户/工具分 scope，自动轮换和撤销，日志/构建/上下文禁明文，轮换需处理进行中任务。

## 648. 多区域部署 Agent 平台要考虑什么？如何处理数据、流量和故障切换？ {#q-648}

**参考答案：**

考虑数据驻留、延迟、供应商可用性、跨区复制和一致性。run 固定主区域/单写所有者，切换用租约/fencing 防双执行，明确 RPO/RTO，敏感数据传输按实际地区与合同要求审核。

## 649. SLA 怎么定？Agent 和普通 API 服务的承诺与衡量方式有什么区别？ {#q-649}

**参考答案：**

SLA 是对外服务承诺及违约安排，SLO 是内部目标；Agent 还需定义任务类型、输入条件、异步完成时限与依赖边界。区分 API 可用性与业务质量，承诺必须可测且由真实负载/评测支持，不能保证所有开放问题正确。

## 650. 队列积压和 Worker 不足时，怎么扩容、限流与降级？ {#q-650}

**参考答案：**

看队列年龄、到达/处理速率与任务成本，按待处理工作量扩 Worker，但受模型配额和下游容量约束。入口限流、公平调度、优先级和降级结合，减少非关键步骤；只扩 Pod 可能放大 429 与重试。

## 651. 灾备（DR）和备份策略中，Agent 的执行状态和业务数据如何恢复？ {#q-651}

**参考答案：**

分别备份权威业务库、run/检查点、事件、对象和密钥元数据，设 RPO/RTO 与跨区恢复方案。恢复后用外部操作 ID/幂等结果对账，再放开任务续跑；定期演练，防止旧快照复活已删除数据。

## 652. Incident 响应：run 失败率突增时，如何定位、止损和恢复？ {#q-652}

**参考答案：**

先确认影响范围和近期发布，暂停高风险写入/新流量，查看错误分布、队列、供应商与 trace。回滚或降级止损，核验状态不明副作用，再逐步恢复；事后复盘根因、监控与回归用例。

## 653. 成本随规模放大时，Agent 平台哪些环节应该优先优化？ {#q-653}

**参考答案：**

先按成功任务拆模型、重试、检索、工具、算力与存储成本，优先优化浪费大且质量影响可控的环节。减少重复上下文/调用、缓存、路由小模型和批处理，压测验证质量/尾延迟，不能盲目降模型或删校验。

## 654. 健康检查、优雅停机、OOM 对 Agent 长任务有什么影响？如何处理？ {#q-654}

**参考答案：**

readiness 控制接流，liveness 判断是否需重启，startup 给慢启动空间；检查不应因短暂供应商失败就重启全部。SIGTERM 停接新任务、检查点/排空，OOM 可能无清理机会，必须持久化和幂等恢复。

## 655. 多租户 Agent SaaS 在部署层如何实现资源隔离与配额管理？ {#q-655}

**参考答案：**

按租户实施队列并发、token/费用、CPU/内存、存储和连接额度，高等级租户可独立 namespace/节点/集群。网络、数据和身份权限仍需单独隔离，ResourceQuota 不等于完整多租户安全。

## 656. CI/CD 流水线里 Agent 服务要跑哪些检查、评测和发布验证？ {#q-656}

**参考答案：**

流水线覆盖类型/单测、工具契约、安全与依赖扫描、任务质量/成本回归、恢复/幂等和迁移兼容。预发布验证流式/审批/取消，金丝雀观察 SLO 和副作用异常，保留镜像/配置/模型版本与回滚。
