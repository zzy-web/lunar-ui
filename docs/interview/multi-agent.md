# 多 Agent 协作

共 **15 题**，题号 **389–403**。 [返回分类总览](./)

> 答案用于面试复习与工程讨论，具体实现请结合项目锁定的版本验证。

> 389–403 所在截图未显示分类标题；此处依据题目内容归类为“多 Agent 协作”。

## 389. 什么场景值得上多 Agent，什么场景单 Agent 或确定性流程就足够？ {#q-389}

**参考答案：**

独立检索、多领域分析、并行验证或强隔离适合多 Agent；共享上下文紧密、步骤短或规则固定时单 Agent/Workflow 更好。先比较成功率、总 token、墙钟时间和协调成本，不能默认数量越多越强。

## 390. Orchestrator–Worker 模式怎么设计任务分解、分发和结果汇总？ {#q-390}

**参考答案：**

协调者输出子任务 ID、目标、输入、依赖、权限、预算与验收，Worker 回传结构化结果和证据。主控限制并发、重试与共享写入，汇总时检查遗漏、冲突和来源，保留失败分支。

## 391. 消息总线（Message Bus）在多 Agent 系统里有什么作用？如何组织通信？ {#q-391}

**参考答案：**

消息总线解耦代理，支持异步投递、广播与背压。消息需有 messageId、correlationId、from/to、schemaVersion 和幂等键，明确至少一次等交付语义，并设置权限、TTL、重试与死信。

## 392. 共享状态与 Agent 隔离怎么取舍？ {#q-392}

**参考答案：**

共享状态利于协作但有竞争与泄露风险；隔离上下文安全清晰但会重复获取信息。常用单一权威状态服务加按任务授权的只读视图，写入走版本条件/事件归并，不共享所有原始对话。

## 393. 两个 Worker 结论冲突时怎么裁决？如何验证证据和决定是否重新执行？ {#q-393}

**参考答案：**

先比较来源权威性、时间、假设和方法，必要时让独立工具复核，不能靠投票数决定事实。无法消解时保留分歧与证据并升级人工，重新执行应有预算和明确要验证的问题。

## 394. Handoff 契约应包含哪些字段？ {#q-394}

**参考答案：**

Handoff 至少带 taskId/runId、目标、上下文摘要、输入/产物引用、已完成/待办、权限、预算、截止时间和验收标准。还需来源、版本、错误与取消约定，避免接收方重复副作用或误解授权。

## 395. Supervisor 模式与 Orchestrator–Worker 模式有什么区别？分别适合哪些场景？ {#q-395}

**参考答案：**

Supervisor 动态选下一代理并持续监控，Orchestrator–Worker 常强调分解后并行执行与集中汇总。具体实现可以同时具备两者，面试应画出真实控制流，说明谁决定下一步和谁维护权威状态。

## 396. 并行 Worker 怎么 fan-out 和 fan-in？如何处理超时、失败与结果合并？ {#q-396}

**参考答案：**

按依赖 fan-out 到有界任务池，所有任务返回可关联结果；fan-in 定义全部成功、部分成功或达到法定数量等策略。设置独立超时、取消、失败重试与最终合并规则，不能按完成顺序误配子任务。

## 397. 多 Agent 的协调成本体现在哪里？如何衡量协作收益是否超过成本？ {#q-397}

**参考答案：**

成本包含额外模型上下文、通信、重复检索、汇总、冲突裁决和更长失败路径。用同任务单 Agent 基线对比成功率、每次成功成本、P95 延迟和人工介入率，只有净收益明确才保留。

## 398. 跨 Agent 的权限和安全域怎么隔离？如何限制共享信息与工具访问？ {#q-398}

**参考答案：**

每个代理单独身份、工具作用域、文件/网络/数据访问，传递必要的结果而非全部凭据和上下文。委派授权不能超过原主体且应可撤销，所有调用仍由服务端校验，跨代理消息不自动获得可信指令地位。

## 399. 长任务里多 Agent 如何做 checkpoint，并在中断后恢复协作？ {#q-399}

**参考答案：**

保存各子任务状态、输入版本、消息游标、产物和外部操作 ID，协调者持久化 DAG/汇总进度。恢复时重发未确认任务并去重，租约防双执行；已成功写动作先核验结果，不能简单从头重跑。

## 400. 人机协同（HITL）在多 Agent 拓扑里应该放在哪里？如何暂停和恢复相关任务？ {#q-400}

**参考答案：**

人工节点设在整体计划风险检查、跨权限委派和高风险动作前，审批只暂停相关依赖分支。持久化请求和具体参数，恢复时校验主体、版本与有效期，同时处理拒绝、超时和取消。

## 401. 怎么评测多 Agent 系统？单 Agent 指标之外还需要哪些协作指标？ {#q-401}

**参考答案：**

除质量/成本/延迟外，测协调轮次、重复劳动率、任务遗漏、冲突率、结果可追溯性、并行利用率与单点故障恢复。注入 Worker 超时、错误证据和消息重复/乱序，验证整体仍能受控结束。

## 402. 从单 Agent 迁到多 Agent 的常见问题有哪些？如何控制迁移复杂度？ {#q-402}

**参考答案：**

常见问题是角色不清、上下文丢失、重复写入、消息循环和总成本失控。只拆独立瓶颈，先规范任务/结果契约，限制拓扑与预算，保持可回退单 Agent 的执行路径。

## 403. 设计一个调研型多 Agent 系统：如何划分 Research、分析与汇总等角色及其协作流程？ {#q-403}

**参考答案：**

Research Worker 按主题收集有时间和链接的证据，分析 Worker 比较观点与可信度，汇总 Agent 生成带引用结论。主控维护去重来源、覆盖清单和预算，对冲突独立复核，证据不足时报告缺口而非互相补造。
