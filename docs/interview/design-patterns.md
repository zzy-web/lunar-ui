# 设计模式

共 **29 题**，题号 **151–179**。 [返回分类总览](./)

> 答案用于面试复习与工程讨论；【推导】保留原文标记，表示题意依据不完整截图补全。实现细节请结合项目锁定的版本验证。

## 151. 设计模式是什么？ {#q-151}

**参考答案：**

设计模式是对重复设计问题的可复用解决思路，描述角色、协作与权衡，而不是固定代码模板。分创建型、结构型、行为型；应从实际变化点选择，避免为了套模式增加抽象。

## 152. 设计模式的意义。 {#q-152}

**参考答案：**

模式为团队提供共同词汇，把易变化部分封装起来，改善扩展、替换与测试。价值应由修改成本和复杂度证明；简单问题直接实现往往更好，模式本身也引入间接层。

## 153. 什么是 MVC？ {#q-153}

**参考答案：**

MVC 将数据与业务放 Model，界面放 View，输入协调放 Controller。用户操作由 Controller 驱动 Model，再更新 View；具体 Web/客户端变体不同，核心是分离表示、业务和输入处理。

## 154. 什么是 MVVM？ {#q-154}

**参考答案：**

MVVM 把界面状态与交互逻辑放 ViewModel，通过绑定把 View 与 ViewModel 关联，Model 保存领域数据。绑定减少手工 DOM 同步，但业务规则仍应合理分层，不能把所有逻辑塞进视图模型。

## 155. 有了 MVC 为什么要有 MVVM？ {#q-155}

**参考答案：**

复杂交互界面中，Controller 容易承担大量 DOM 同步工作；MVVM 用声明式绑定和可观察状态减少手工同步。它不是全面替代 MVC，选型取决于界面复杂度、工具链和团队习惯。

## 156. 实现一个 MVVM 示例。 {#q-156}

**参考答案：**

最小示例可用 reactive({ name: '' }) 作为 ViewModel，input 的 v-model="state.name" 双向绑定，文本节点显示 state.name；用户输入更新状态，状态变化自动更新视图。可参见本分类后的代码示例，领域数据持久化仍需单独 Model/服务。


**Vue 3 最小 MVVM 示例：**

```vue
<script setup>
import { reactive } from 'vue'
const state = reactive({ name: '' })
</script>

<template>
  <label>姓名 <input v-model="state.name" /></label>
  <p>你好，{{ state.name || '访客' }}</p>
</template>
```

这里只演示绑定。真实业务的加载、保存和校验应交给独立服务与明确的交互状态。

## 157. 面向对象基本特性。 {#q-157}

**参考答案：**

封装隐藏实现并暴露接口，继承复用与特化，多态让同一接口适配不同实现。实践中常优先组合，保持对象不变量和可替换契约，而不是把所有复用都做成深继承树。

## 158. 面向对象的设计原则。 {#q-158}

**参考答案：**

SOLID 包含单一职责、开闭、里氏替换、接口隔离、依赖倒置；另有 DRY、KISS 与最少知识等原则。原则用于判断变化成本，需结合场景取舍，不能机械地把每个类拆成只有一个方法。

## 159. 单例模式（Singleton Pattern）。 {#q-159}

**参考答案：**

单例确保某个作用域只有一个实例并提供访问点，如应用配置或连接管理器。JS 模块常可实现模块级共享，但多进程/多副本并非全局唯一；注意隐藏依赖、测试隔离和生命周期。

## 160. 工厂模式（Factory Pattern）。 {#q-160}

**参考答案：**

工厂封装创建逻辑，调用方按条件获取符合共同接口的对象，例如按渠道创建支付客户端。简单工厂集中分支，工厂方法交给子类，抽象工厂创建相关产品族；适合构造过程会变化时。

## 161. 建造者模式（Builder Pattern）。 {#q-161}

**参考答案：**

建造者分步骤构造复杂对象，最后 build 校验并产出结果，如请求配置或报表。它把构造过程与表示分开，避免超长构造参数；简单数据对象不必额外引入 Builder。

## 162. 原型模式（Prototype Pattern）。 {#q-162}

**参考答案：**

原型模式通过复制已有对象创建新对象，适合初始化昂贵或对象形态复杂的场景。需要定义浅/深复制与共享资源语义；它和 JavaScript 的 prototype 继承有关联但不是同一个概念。

## 163. 适配器模式（Adapter Pattern）。 {#q-163}

**参考答案：**

适配器将已有接口转换为调用方期待的接口，如把第三方支付返回值映射为统一订单接口。重点是兼容而不修改原实现，需保留错误、取消和数据语义，避免只改字段名而丢失契约。

## 164. 装饰者模式（Decorator Pattern）。 {#q-164}

**参考答案：**

装饰者包装同一接口对象，在不改原类的情况下叠加日志、缓存等行为。包装层可组合但顺序影响结果，注意资源清理与错误传播；与只做接口转换的适配器不同。

## 165. 观察者模式（Observer Pattern）。 {#q-165}

**参考答案：**

观察者建立一对多订阅关系，主题变化时通知观察者。典型流程是 subscribe、notify、unsubscribe；处理取消订阅、重入和异常隔离，避免长期监听造成内存泄漏。

## 166. 策略模式（Strategy Pattern）。 {#q-166}

**参考答案：**

策略将可替换算法封装在共同接口后，如不同折扣计算器。调用方选择策略并委托执行，减少反复分支；策略选择规则与算法本身应分离，简单策略也可直接用函数。

## 167. 命令模式（Command Pattern）。 {#q-167}

**参考答案：**

命令把操作及参数封装成对象，统一 execute，可扩展撤销、排队和审计，如编辑器操作。undo 需要保存逆操作或快照，不是每个外部副作用都能撤销；重试要有幂等键。

## 168. 状态模式（State Pattern）。 {#q-168}

**参考答案：**

状态模式把不同状态下的行为放入对应状态对象，由上下文委托并控制合法转换，如订单流转。适合状态相关分支持续增长的场景；必须校验转换，状态持久化和并发一致性另行实现。

## 169. 访问者模式（Visitor Pattern）。 {#q-169}

**参考答案：**

访问者把操作从稳定的对象结构中抽出，通过 accept/visit 为不同节点分派行为，如 AST 分析。容易新增操作，但新增节点类型可能需要修改所有访问者，适合结构稳定而操作经常扩展时。

## 170. 【推导】模板方法模式（Template Method Pattern）。 {#q-170}

**参考答案：**

模板方法在基类定义算法骨架，由子类覆盖部分步骤，如导入流程的解析和校验。保持整体顺序一致但引入继承耦合；需控制可覆盖点，也可用组合函数实现同类需求。

## 171. 中介者模式（Mediator Pattern）。 {#q-171}

**参考答案：**

中介者集中管理对象间协作，避免组件互相直接引用，如表单字段协调或聊天室。它降低网状依赖，但中介者可能过大；按业务范围拆分，不应变成全局万能对象。

## 172. 备忘录模式（Memento Pattern）。 {#q-172}

**参考答案：**

备忘录保存对象的可恢复快照，并由管理者维护历史，如编辑器撤销。快照应封装内部状态、限制容量，必要时增量保存；恢复本地状态不自动撤销已经发生的外部副作用。

## 173. 【推导】解释器模式（Interpreter Pattern）。 {#q-173}

**参考答案：**

解释器用语法规则及表达式树解释小型语言，如简单过滤 DSL。适合语法简单、稳定的场景；复杂语法应使用成熟解析器，并限制表达式能力与执行成本，不能直接 eval 用户文本。

## 174. 享元模式（Flyweight Pattern）。 {#q-174}

**参考答案：**

享元共享大量对象中的不可变内部状态，把位置、用户等外部状态由调用方传入，如字形元数据。可节省内存，但共享对象不得携带请求级可变状态，否则会造成串扰。

## 175. 【推导】责任链模式（Chain of Responsibility Pattern）。 {#q-175}

**参考答案：**

责任链把处理器串联，每个处理器决定处理、拒绝或传给下一节点，如中间件与审批链。定义顺序、终止条件和错误传播；避免某个节点漏传或重复调用 next。

## 176. 桥接模式（Bridge Pattern）。 {#q-176}

**参考答案：**

桥接把抽象与实现两个变化维度分开，通过组合关联，如多种图形与多种渲染后端。与适配已有接口的适配器相比，它更强调事先设计两套独立扩展层次。

## 177. 组合模式（Composite Pattern）。 {#q-177}

**参考答案：**

组合以统一接口处理叶子和容器，递归表示树形结构，如菜单、文件目录。调用方可统一遍历/操作；需避免循环引用，明确父子所有权与聚合操作语义。

## 178. 迭代器模式（Iterator Pattern）。 {#q-178}

**参考答案：**

迭代器将遍历方式封装，与容器内部结构解耦。JS 通过 Symbol.iterator 返回带 next 的对象，结果为 { value, done }；大集合可惰性遍历，并考虑提前结束时的资源清理。

## 179. 代理模式（Proxy Pattern）。 {#q-179}

**参考答案：**

代理保持目标接口并控制访问，可实现延迟加载、权限、远程调用或缓存。装饰者重在增加行为，代理重在访问控制，但结构可能相似；远程代理还需处理超时、失败与一致性。
