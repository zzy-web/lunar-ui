# 可观测性（日志与成本分析）

共 **15 题**，题号 **598–612**。 [返回分类总览](./)

> 答案用于面试复习与工程讨论，具体实现请结合项目锁定的版本验证。

## 598. Agent 系统可观测性要覆盖哪几个层面？ {#q-598}

**参考答案：**

覆盖业务任务、Harness/工作流、模型、工具/检索、基础设施与安全审计。日志解释事件，指标反映趋势，trace 关联调用；统一 run/tenant/version 标签并控制敏感数据和高基数成本。

## 599. runId 和 correlationId 在分布式追踪里分别有什么作用？如何贯穿调用链？ {#q-599}

**参考答案：**

runId 标识一次业务执行，correlationId 串联跨服务请求/事件，traceId 标识一次分布式追踪，三者可关联但不必相同。创建时生成并通过 HTTP、队列和工具调用传递，身份字段必须由可信端设置。

## 600. OpenTelemetry 如何接入 Agent/Harness，追踪模型、工具和工作流执行？ {#q-600}

**参考答案：**

为 run/阶段、模型调用、工具、检索等创建 span，跨 HTTP/队列传播 trace context，异步分支使用父子关系或 links。采集延迟、状态和必要用量，内容脱敏；trace 不应无限携带完整提示和工具结果。

## 601. token 用量与 LLM 成本该采集哪些字段？如何计算和归因？ {#q-601}

**参考答案：**

采集供应商/模型/版本、输入/输出/缓存/推理等实际 usage、单价版本、请求/run/租户和重试。按供应商计费规则避免重叠字段重复计数，估算与账单对账；最终优化看每次成功任务成本。

## 602. 多租户 Agent 产品怎么做按租户的用量统计、成本核算和配额监控？ {#q-602}

**参考答案：**

可信 tenantId 贯穿请求与模型/工具计量，保留不可变用量明细并按日/月聚合。执行前预留、执行中扣减、结束结算，设置预算与异常告警；缓存/共享资源成本需定义清晰分摊规则。

## 603. Tool 调用延迟怎么监控？慢在哪一层如何定位？ {#q-603}

**参考答案：**

分解排队、授权/校验、执行、下游等待和序列化耗时，按工具/版本统计 P50/P95/P99 与超时。利用 span 看瓶颈，再查连接池、限流、CPU 或数据量，平均延迟不足以定位尾部问题。

## 604. RAG 空检索和低置信命中怎么纳入监控与告警？ {#q-604}

**参考答案：**

记录检索次数、过滤后候选数、空结果率、相似度分布和最终答复质量，按知识源/版本/租户聚合。阈值需业务校准，分数低不必然错误；空检索突增结合索引同步/ACL/查询变化告警。

## 605. Agent 日志里的 PII 与敏感字段如何脱敏和控制访问？ {#q-605}

**参考答案：**

采集前按 schema 删除/掩码凭据与个人信息，必要字段哈希或令牌化，原始内容单独加密限权。配置访问审计和保留期，防止模型/工具错误把秘密带入堆栈或日志；事后正则清洗不是唯一防线。

## 606. 生产 Agent 仪表盘最少要有哪些指标？ {#q-606}

**参考答案：**

至少有任务成功/失败、质量、首响应和总延迟、队列等待、模型/工具错误、人工接管、用量/费用及活跃并发。按版本/租户/任务下钻，附容量和数据新鲜度，不应只放 token 曲线。

## 607. Agent 告警怎么设才不狼来了？如何分级、聚合和抑制无效告警？ {#q-607}

**参考答案：**

按用户影响、持续时间与错误预算设置告警，分级通知、聚合同根因并抑制依赖故障的重复报警。结合多窗口阈值与基线，告警附 run/trace 和处置手册，定期复盘误报/漏报。

## 608. Agent 服务 SLO 怎么定义？成功率、延迟和任务完成质量如何衡量？ {#q-608}

**参考答案：**

SLO 定义测量窗口和合格任务，如在 deadline 内通过业务验收的比例、首响应/总耗时分位数及安全违规上限。区分依赖失败和用户取消但明确统计口径，离线质量作为补充，不仅计算 HTTP 200。

## 609. Harness 结构化事件和 OpenTelemetry 如何关联，避免重复记录和链路断裂？ {#q-609}

**参考答案：**

Harness event 带 run/step/call ID 和 trace/span ID，OTel 用来表达调用时序，事件日志表达可恢复业务事实。明确唯一采集方避免重复计量，异步链路传 context/links，采样 trace 不得丢关键审计。

## 610. 流式输出和长 run 场景下，trace 如何组织和关联？ {#q-610}

**参考答案：**

长 run 可每阶段/尝试独立 trace，以 runId 和 span links 关联，避免单个数小时 span 难采集。SSE 订阅连接另建 trace，不与任务生命周期混同；断线重连保留执行链关联。

## 611. 成本突增或 token 暴涨时，排查路径应该怎么设计？ {#q-611}

**参考答案：**

先按租户、版本、模型和任务找增长来源，再看请求量、输入/输出、缓存命中、重试和循环次数。对比发布/知识切块变化，紧急启用配额或降级止损，再用轨迹复现根因并对账费用。

## 612. 可观测数据、评测数据和审计日志有什么区别？如何关联与分开管理？ {#q-612}

**参考答案：**

观测数据用于运行诊断，评测数据用于质量比较，审计用于可追溯主体与动作证据。用 run/版本/来源关联，但分别设置权限、保留、完整性和采样策略；审计不可因调试日志采样而丢失。
